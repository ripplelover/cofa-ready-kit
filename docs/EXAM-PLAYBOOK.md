2026-10-31(토) 10:00–14:00 KST, 09:40 접속 준비. 시간 배분은 준비 키트의 제안이며 실제 타이머와 당일 공지가 우선이다. 시험 중에는 Cofa 안에 받은 이 문서를 편집기·제공 Codex로 읽고, 외부 브라우저나 준비용 AI 채팅으로 시험 내용을 옮기지 않는다.

- 09:50 별도 이메일로 안내될 자리 이탈 관련 내용을 확인한다. 자세한 준비물·제한은 [규칙 요약](RULES.md), 원문은 참가자 PDF가 기준이다.

## 1. 어디에 입력하는지 먼저 구분한다

| 화면 위치 | 하는 일 | 입력 예 |
| --- | --- | --- |
| 왼쪽 파일 목록·가운데 편집기 | 실제 README·코드·문서 확인 | 파일을 직접 열어 읽기 |
| 아래 Terminal의 일반 셸 | 프로그램 실행 | `codex`, `git clone ...` |
| Terminal 안 OpenAI Codex의 입력란 | AI에게 조사·수정·검증 요청 | README의 시작 요청, `/model`, `$cofa-build` |
| 오른쪽 실무자 에이전트 | 업무 목적·처리 기준 확인 | “결과를 아직 모르는 상태는 어떻게 처리하나요?” |
| Browser | 실제 화면을 본인이 확인 | 과제가 웹일 때 실제 포트·경로 입력 |
| Cofa Helper / 문제 신고 | 사용법 / 반복 장애 해결 | 단계·시각·실제 오류 문구 전달 |

첨부 화면처럼 **OpenAI Codex와 Ask Codex가 이미 보이면 바로 그 칸에 시작 요청을 보낸다.** 일반 셸만 있으면 `codex`를 실행한다. `/model`에서 실제 제공된 허용 모델을 확인한다. 개인 로그인·외부 AI·API 키를 추가하지 않는다. `$스킬명`은 일반 셸 명령이 아니다.

시작 요청은 Codex가 실제 과제 폴더를 확인하고 공개 키트를 받도록 한다. 필요한 지침은 파일로 읽으므로 설치 없이도 적용할 수 있다. 도구 권한 창이 나오면 명령과 경로가 요청한 작업인지 본인이 확인한다. 다운로드나 파일 읽기가 실패하면 그 사실을 표시하고 아래 복구표를 따른다.

**첫 답에서 확인할 것:** 실제 과제 안내의 경로, 필수 기능·제출물, 확인 방법, 중요한 업무 질문. `.cofa-kit/README.md`나 합성 예제를 실제 문제로 읽은 답이면 즉시 바로잡는다.

## 2. 결과를 확인하며 같은 대화에서 진행한다

진행은 Codex가 필요한 지침을 골라 적용한다. 본인은 아래 세 가지를 반복한다.

1. **업무 기준을 확인한다.** 답에 따라 구현이 달라지는 질문만 실무자에게 직접 보내고 실제 답변을 Codex에 전달한다. 답을 못 받은 내용은 미확인, 진행을 위해 실제로 선택한 내용은 임시 가정으로 구분한다.
2. **실제 결과를 본다.** 무엇을 바꿨고, 어떤 입력에 어떤 결과가 나왔는지 확인한다. 계획만 있거나 “완료”라는 말만 있으면 실행 결과를 요청한다.
3. **시간과 우선순위를 알려 준다.** 화면의 실제 남은 시간을 전달한다. 반복 오류·필수 실패가 있으면 그것부터 고친다.

필요할 때 다음 문장 중 하나만 보낸다. 특별한 명령어가 아니라 일반 대화다.

```text
실무자가 실제로 답한 기준은 다음과 같아: [받은 답변]. 이를 반영해 진행해 줘.
```

```text
확인된 필수조건부터 구현하고 관련 검증까지 진행해 줘.
변경 파일·실제 명령과 결과·미검증·내가 직접 할 일만 짧게 알려 줘.
```

```text
화면에서 확인한 남은 시간은 [숫자]분이야.
필수 오류와 누락, 실제 제출 문서, 저장·제출 준비를 우선해 줘.
```

### 실제 문제에 따라 달라지는 준비

| 받은 과제 | Codex가 먼저 할 일 | 본인이 확인할 점 |
| --- | --- | --- |
| 기존 코드·API의 오류 수정 | 기존 실행법·계약·테스트 확인 → 오류 재현 → 최소 수정 → 같은 재현과 회귀 검사 | 원인이 설명되는가? 정상 동작과 API가 유지되는가? |
| 새 기능·서비스 | 기존 스택으로 입력→처리→결과 하나를 완성하고 필수조건 확장 | 고정 예시 화면이 아니라 실제 입력이 처리되는가? |
| CSV·반도체 데이터 | 행 단위·분모·중복/재검·시점·키 관계부터 확인 | 작은 손계산과 일치하는가? 관측 차이를 원인으로 단정하지 않는가? |
| 문서·분석·의사결정 | 근거·가정·대안·판단 기준을 확인하고 요구 형식 작성 | 근거와 결론이 이어지는가? 하지 않은 검증을 썼는가? |

기존 프로젝트 과제면 `cofa-build`의 [기존 코드 수정 지침](../skills/cofa-build/references/existing-project.md)을 읽는다. 반도체 과제에만 `cofa-semiconductor`와 [반도체 실습](SEMICONDUCTOR-WALKTHROUGH.md)을 적용한다. 실제 CSV 결합이 필요할 때만 [조인 검사](DATA-JOIN.md)를 쓴다. 새 대시보드나 MCP를 무조건 추가하지 않는다.

공식 사이트의 주문 API 화면은 **공개 시연용 예시**다. 실제 과제 스택·파일명·문제를 예고하지 않는다. 예시의 `DECISIONS.md`를 모든 과제의 필수 파일로 만들지 않는다. 사례와 근거는 [조사 결과](RESEARCH.md)에 있다.

웹 결과물이 필요하면 Codex가 서버를 `0.0.0.0`으로 열고, 본인이 Browser에서 실제 포트·경로를 맞춰 버튼·입력·오류를 확인한다. 서버 터미널을 유지한다. 사람이 관찰한 결과만 전달하며 UI 자동 조작은 사용하지 않는다. 화면이 없는 코드·분석 과제에 Browser를 추가할 필요는 없다.

### 여러 스킬을 같이 쓰고 싶을 때

기본 흐름에서는 필요한 스킬 파일을 직접 읽는다. 이름으로 호출하려면 [설치·호출 설명](SKILLS-BEGINNER.md)의 선택형 설치를 먼저 하고 목록을 확인한다.

```text
$cofa-build $cofa-verify
기존 요구와 API 계약을 유지해 최소 수정하고, 관련 정상·실패 사례를 검증해 줘.
```

위 요청은 **같은 Codex가 두 지침을 적용**하는 것이며 두 AI의 자동 병렬 실행이 아니다. 설치한 스킬이 예전 버전이거나 이름이 안 보이면 현재 키트의 해당 `SKILL.md`를 직접 읽도록 한다. 설치 충돌을 없애려고 기존 파일을 삭제하지 않는다.

### 시간이 얼마나 남아야 하나

| 과제 시작 후 경과 | 권장 우선순위 |
| --- | --- |
| 0–30분 | 감독 절차, 실제 요구·기존 실행법·중요 업무 질문 |
| 30–115분 | 가장 중요한 흐름부터 구현·검증하고 필수조건 확장 |
| 115–145분 | 오류·경계·회귀 검사, 필요한 화면 수동 확인 |
| 145–170분 | 필수 문서·실행법·한계·본인 이해·저장 확인 |
| 170분부터 | 직접 제출 절차 시작 |

화면의 남은 시간이 우선이다. 늦게 시작해도 14:00은 연장되지 않는다. 서술형 30분, 질문 준비 대기, 업로드 여유를 먼저 남긴다. 대기는 브리프 약 5분, 상세 가이드는 최대 10분과 재시도 가능성을 설명한다. 토큰별 감점 공식은 공개되지 않았으며, 같은 설명·불필요한 문서 읽기·설정을 반복하기보다 실제 검증에 시간을 쓴다.

## 3. 제출 준비와 마지막 단계는 본인이 확인한다

**아직 제출 확정 전일 때** Codex에 마지막 점검을 요청한다.

```text
실제 과제 안내의 필수 파일·내용과 현재 구현을 대조해 줘.
정상·오류·경계 검증의 실제 결과, 실패·미검증, 남은 한계를 확인해 줘.
요구된 제출 문서를 그 사실에 맞게 정리하고 하지 않은 작업은 적지 마.
내가 설명할 선택·근거·한계와 직접 확인할 저장·화면 항목을 짧게 알려 줘.
제출 버튼은 내가 누를게. 확정 후에는 AI 작업을 중단해 줘.
```

문제·선택 이유·검증 결과·한계를 본인이 설명할 수 있는지 확인한다. 시간이 있으면 **확정 전에만** `cofa-explain` 지침으로 짧게 연습한다. 스크립트가 출력한 PASS나 파일 존재만으로 실제 과제 완료를 판단하지 않는다.

- [ ] 작업 종료 10분 전부터 저장·필수 파일·내용·경로·충돌 표시를 확인한다.
- [ ] 제출 미리보기가 전체 파일 목록이 아닐 수 있음을 기억하고 본인이 제출물을 확정한다.
- [ ] **확정 후 파일 수정·AI·Skill·MCP 사용을 중단한다.**
- [ ] 질문 준비가 끝나면 본인이 시작/문제 풀기를 누른다. 첫 타이머가 시작된다.
- [ ] **6문항×5분**, AI와 복사/붙여넣기 없이 본인이 답한다. 이전 문항으로 돌아갈 수 없고 답 제출 후 다음 시간이 시작된다.
- [ ] 녹화·자료 업로드를 기다리고 완료 화면의 **제출 ID·시각·파일 수·크기**를 확인한 뒤 닫는다.

파일 확정만으로 응시가 끝나는 것은 아니다. 반복 오류는 단계·시각·오류를 문제 신고로 전달한다. 문의·재접속으로 타이머가 멈추지는 않는다. 근거: 참가자 브리프 p.1, 상세 가이드 pp.3–5.

## 제출 확정 전에 막혔을 때만 확인

| 증상 | 바로 할 일 |
| --- | --- |
| Codex가 공개 키트를 못 받음 | 아래 일반 터미널 명령을 허용된 환경에서 사용. 접근 차단이면 우회하지 않고 Helper/문제 신고, 기본 Codex로 실제 과제 진행 |
| 키트는 있는데 스킬이 안 보임 | `.cofa-kit/skills/cofa-triage/SKILL.md` 같은 실제 파일을 읽게 한다 |
| Python·설치·MCP 문제 | 기본 흐름은 파일 읽기로 계속. 도구가 필요한 경우만 [CLI](TOOLS.md)·[설정](SETUP.md) 확인 |
| 파일 읽기·명령이 정책상 차단됨 | 읽거나 실행됐다고 가정하지 않음. 실제 오류를 Helper/문제 신고로 확인하고 개인 인증·감독 설정을 변경하지 않음 |
| 같은 오류가 반복됨 | [오류 복구 요청](../prompts/RESCUE.md)으로 작은 입력의 기대값·실제값부터 재현 |
| 새 대화·재접속 | [SCENARIO의 재개 요청](../prompts/SCENARIO.md#재개할-때)으로 실제 파일·기록 확인 후 계속 |

일반 셸에서 직접 받을 때는 **실제 과제 폴더에서 `.cofa-kit`이 없음을 확인한 뒤** 아래 한 줄만 실행한다. 그 폴더 안으로 `cd`하지 않는다. 끝나면 제공 Codex에 `.cofa-kit/prompts/SCENARIO.md를 읽고 진행해 줘`라고 요청한다.

```bash
git clone --depth 1 https://github.com/ripplelover/cofa-ready-kit.git .cofa-kit
```

기존 폴더는 [충돌·업데이트 설명](MANUAL.md#4-3-cofa-kit이-이미-있는-경우)을 따른다. 시험 중에는 Git Push, 개인 PC 파일 업로드, 문제·파일·결과의 외부 전송, Computer Use를 하지 않는다.
