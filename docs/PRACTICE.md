# 오늘 해볼 60분 연습

[시험 첫 화면](../README.md) · [전체 문서 지도](INDEX.md)

이 연습은 제작자가 만든 합성 시나리오입니다. 실제 출제 내용을 예측하지 않으며 해설이나 완성 코드를 제공하지 않습니다. 시험 자료를 이 저장소에 넣지 마세요.

## 시나리오

공정 검토 담당자가 CSV의 누락·중복 때문에 매번 수작업으로 확인하고 있다고 가정합니다. `examples/defects.csv`를 읽고, 데이터 품질 요약과 우선 검토할 항목을 제시하는 **작은 로컬 도구**를 만들어 보세요. 파일 내용과 열 이름을 직접 확인한 뒤 범위를 정합니다. 웹 UI가 꼭 필요하지는 않습니다.

필수 결과는 실행 방법이 있는 README, 원본을 수정하지 않는 분석 코드, 계산 규칙을 설명한 결과 파일, 정상 입력과 불완전 입력을 확인하는 테스트입니다. 실제 과제에는 이 파일명을 강제하지 않습니다.

먼저 답해야 하는 질문:

- 중복은 모든 열이 같은 행인가, 특정 ID가 같은 행인가?
- 빈 값은 0인가, 알 수 없음인가? 어떤 결과에 영향을 주는가?
- '우선 검토'는 빈도, 비율, 손실 비용 중 무엇으로 정하는가? 근거가 없다면 무엇을 확정하지 않을 것인가?
- 이미 집계된 값과 개별 행을 혼합해 중복 집계할 가능성은 없는가?

## 시간 배분

| 시간 | 행동 | 스스로 확인할 것 |
|---|---|---|
| 0–8분 | 파일 읽기, triage 스킬로 요구사항 정리 | 확인 사실과 가정을 구분했나 |
| 8–15분 | 범위와 계산 규칙 선택 | 핵심 결과를 작은 입력으로 손계산할 수 있나 |
| 15–35분 | 최소 경로 구현 | 입력 → 계산 → 저장이 실제로 이어지나 |
| 35–45분 | 정상·결측·중복·빈 데이터 검증 | 기대 결과를 구현과 독립적으로 정했나 |
| 45–50분 | 실행 증거·한계 문서 정리 | 하지 않은 일을 완료라고 쓰지 않았나 |
| 50–60분 | AI를 닫고 직접 설명 | 왜 이렇게 만들었는지 90초씩 말할 수 있나 |

막히면 기능을 늘리는 대신 입력 파일 하나와 정확한 계산 하나를 끝내세요. 파일의 잘못된 값도 정상처럼 보이도록 꾸미지 않습니다.

## 합격 여부가 아닌 자기 점검

1. 다른 폴더에서 README 명령만으로 실행할 수 있는가?
2. 필터·집계 조건을 바꿨을 때 결과를 설명할 수 있는가?
3. 결측·중복 처리를 테스트에서 실제로 확인했는가?
4. AI가 처음 제안한 것 중 무엇을 거절하거나 수정했는가?
5. 시간이 20분 더 있다면 무엇을 먼저 검증할 것인가?
6. 결과를 업무에 바로 사용할 수 없는 이유가 있다면 무엇인가?

내일의 후속 서술형은 제출물과 작업 기록에 기반합니다. 위 질문은 사고 연습용이며 실제 문항이나 정답 형식이 아닙니다. **후속 단계가 시작되면 연습 스킬·프롬프트·MCP를 사용하지 않고 직접 답합니다.**
