## 무엇을 하는 시험인가

제공 웹 IDE에서 실제 과제 안내를 읽고 Codex를 활용해 요구 결과물을 만든 뒤 제출한다. 이어서 제출물·작업 기록을 바탕으로 준비되는 서술형 질문에 직접 답한다. 가이드의 할 일 앱, 화면에 보이는 코드와 질문은 사용법 예시다. **실제 문제, 필수 산출물, 파일명, 세부 채점 가중치는 이 PDF에 공개되어 있지 않다.** [3 pp.1–4]

계획 문서나 협업 기록 같은 **과제 제출 문서**는 제공된 코딩 에이전트와 함께 작성할 수 있다. 그 사실만으로 불이익을 받지 않는다고 안내한다. 선택 이유, 확인한 결과, 한계가 실제 구현과 맞는지 응시자가 확인해야 한다. **제출 후 서술형 답변은 AI 없이 직접 작성**한다. [3 pp.3–4]

상세 가이드의 “5개 질문” 캡처는 **예시**다. 준비는 브리프와 FAQ의 6문항 기준으로 하고, 실제 화면에 표시된 수를 확인한다. 질문 준비 시간은 풀이 제한 시간에는 포함되지 않지만 전체 14:00 마감에는 포함된다. 180분+30분 외의 시간을 별도 휴식 시간으로 해석하면 안 된다. [3 pp.4–5]

공식 권고는 **작업 제한 시간 종료 10분 전 제출 시작**이다. 미리보기는 파일 일부만 보여줄 수 있다. 확정하면 파일을 고칠 수 없으며, 질문 답변과 자료 처리가 끝난 뒤 완료 화면의 제출 ID·시각·파일 수·크기까지 확인해야 한다. 최소 응시 시간은 없고 모두 마치면 먼저 종료할 수 있다. [3 pp.3–4]

## 감독과 장비

- 컴퓨터 한 대, 모니터 한 대, 독립된 폐쇄 공간. 투명한 문·창문·유리벽 등 외부 개입을 막기 어려운 부분은 가린다. [3 p.1]
- 컴퓨터 웹캠과 별도 Proctor 촬영용 휴대폰을 준비한다. 휴대폰·태블릿을 컴퓨터 웹캠 대신 사용하지 않는다. 전체 얼굴과 두 귀가 보이도록 한다. [3 p.1]
- **노트북 내장 키보드 외에 연결된 유선 키보드는 1개까지 허용, 블루투스 키보드는 불가.** [2 p.1]
- 휴대폰 충전선은 응시 종료까지 연결. 노트북도 전원 어댑터 연결. 컴퓨터·휴대폰 방해금지 모드 설정. 다운로드·업로드 각각 5Mbps 이상 권장. [1 p.1], [2 p.1]
- 권장 휴대폰: iPhone 11 이상·iOS 16 이상 또는 Android 11 이상·RAM 4GB 이상, 여유 저장 공간 1GB 이상. [2 p.1]
- 전체 화면을 공유하며 브라우저 전체화면을 유지한다. 창·탭 하나만 공유하는 것으로 대체할 수 없다. [3 pp.1, 5]
- 식음료는 자리에서 카메라·모니터를 가리지 않고 섭취할 수 있다. 감독 연결과 타이머는 유지된다. 이석은 09:50 추가 안내를 확인한다. [1 p.1], [2 p.1]

## Proctor 연결과 본인 확인 순서

1. 공식 안내의 설치 경로로 앱을 설치한다. **설치 QR과 응시 연결 QR은 다르다.** Android 설치 중 임시로 허용한 출처·보안 설정은 공식 가이드의 마무리 절차대로 복원한다. [2 p.1]
2. PC에서 설치 완료 후 연결 단계를 열고, 새 연결 QR을 **Proctor 앱 안에서** 스캔한다. PC에 연결 완료 표시가 나오는지 확인한다. 연결만으로 녹화가 시작되는 것은 아니다. [3 p.1]
3. 본 과제에서 “과제 시작”을 누르면 녹화가 자동 시작된다. **녹화 시작 후** 휴대폰 거치 → 신분증 → 안경 순서로 확인한다. [2 p.1], [3 p.2]
4. 옆으로 펼친 팔의 손끝 위치 정도에 휴대폰을 세로로 거치하고 손·키보드·얼굴·모니터가 함께 보이게 맞춘다. [2 p.1]
5. 신분증은 PC 웹캠이 아니라 **Proctor 휴대폰 카메라**에 얼굴 옆으로 제시한다. 실물 주민등록증·운전면허증·여권 중 하나이며 모바일 신분증은 불가. 안경 착용자는 앞면과 양쪽 안경다리의 안팎을 보여준다. [2 p.1]

## 과제 화면에서 필요한 조작

터미널에 `codex`를 입력하고 작업 폴더를 확인한다. `/status`로 모델·권한을 확인하고 `/model`에서 안내된 모델을 선택한다. 승인 대기인지, 실행 중인지, 완료인지 구분한다. 승인을 기다리는 상태는 응답 지연이 아니다. 제공 환경의 허용 명령은 별도 승인 없이 실행될 수도 있다. [3 p.2]

서비스 미리보기는 **플랫폼 Browser**를 사용한다. 서버를 `0.0.0.0`에 바인딩하고 실제 실행 포트와 경로를 입력한다. `3000`은 예시이며 고정 요구사항이 아니다. 서버 터미널을 유지한 채 응시자가 버튼·입력·이동을 직접 확인한다. 연결 안 됨 → 서버 오류·종료 여부 → 실제 포트 → 바인딩 → 경로 순서로 확인한다. 외부 터널을 만들 필요가 없다. [3 p.3]

MCP는 필요할 때 탭의 서버 설정 JSON을 편집·저장하며 준비된 Codex 설정에 반영된다. 구체적인 schema와 지원 기능은 실제 환경 안내로 확인한다. Skill도 제공 환경의 적용 방법을 따른다. 공개 저장소를 clone했다는 이유만으로 자동 등록되었다고 가정하지 않는다. [3 pp.3, 5]

자동 저장 표시를 확인한다. AI와 에디터가 같은 파일을 바꾸면 외부 변경을 불러올지 현재 에디터 내용을 저장할지 비교한 후 선택한다. 제출 직전에 “저장됨”을 확인한다. [3 p.3]

출처: [3 pp.2, 5]. 신고에는 발생 시각, 단계, 직전 행동, 오류 문구를 남긴다. 서술형 문제 오류는 문항 번호도 기록한다. 키·토큰·비밀번호는 적지 않는다. 서술형 창에는 별도 신고 버튼이 없으므로 상단에 접근하기 어려우면 발생 내용을 기록한다. 문의 자체로 시간은 멈추지 않는다. [3 p.5]

창을 실수로 닫았다면 같은 접속 링크로 재입장하고 웹캠·전체 화면 공유·휴대폰 연결을 복구한다. 저장된 내용으로 이어가며 타이머는 계속 흐른다. 감독 경고만으로 부정행위가 확정되는 것은 아니므로 안내에 따라 복구하고 시험을 이어간다. [3 p.5]

## 후속 서술형과 기록

AI, 외부 기기의 AI, 복사·붙여넣기를 사용할 수 없다. 첫 문제는 시작 버튼을 누르면, 다음 문제는 직전 답안을 제출하는 순간부터 시간이 계산된다. 이전 문항으로 돌아가거나 확정 답안을 수정할 수 없다. 시간이 끝나면 작성 중인 내용이 확정된다. 질문의 전제가 실제 구현과 다르면 차이를 밝히고 자신의 작업을 설명한다. [3 p.4]

대화, 터미널 세션, AI 설정, Git 로그·diff, 테스트 결과, 코드·문서 등이 수집된다. 토큰 사용량은 추적되며 간접 평가에 활용될 수 있다고 안내한다. 토큰을 줄이면 자동으로 높은 점수라는 공식은 제공되지 않는다. 기록에 없는 테스트나 판단을 사후에 지어내지 않는다. [3 p.5]

## 이 키트와 규칙을 대조한 결과

2026-10-31에 첨부 PDF 3개 총 7쪽과 현재 안내·스킬·소스를 다시 대조했다. 공개된 규칙에 어긋나는 사용을 유도하는 기능·지침은 발견하지 못했으며, 외부 전송 금지를 약하게 읽힐 수 있던 시간표 문구는 명확히 고쳤다. 이는 문서·소스 검토 결과이며 **주최 측이 이 키트를 개별 승인했다는 뜻은 아니다.**

공개 Git Clone 허용은 모든 외부 접근·데이터 전송의 포괄 허가가 아니다. MCP 설정은 제공 탭의 안내를 따르며, 문서의 일반 CLI 등록 예시는 제공 환경에서 허용할 때만 쓴다. 실제 Cofa의 지원 여부·권한은 별도로 확인한다.

**공식 규칙과 키트의 운영 선택을 구분한다.** 공식 금지는 후속 서술형에서의 AI 사용과 전 단계 Computer Use다. 이 키트는 경계 혼동을 줄이기 위해 제출 확정 즉시 AI를 멈추고 브라우저 자동 테스트도 사용하지 않는 방식을 택했다. 특정 브라우저 테스트 도구에 대한 주최 측 개별 판정이라고 주장하지 않는다.

키트는 Cofa의 제출 상태를 감지하거나 금지 행동을 자동 차단하지 않는다. 특히 CLI `run`은 지정한 명령을 실행하는 도구이며 외부 통신을 막는 샌드박스가 아니다. 허용된 로컬 검증에만 사용하고 확정 뒤에는 본인이 사용을 중단한다. 로컬 MCP의 읽기 전용은 과제 입력·결과 파일을 수정하는 도구를 제공하지 않는다는 의미이며 임시 출력 파일·Python 캐시까지 전혀 쓰지 않는다는 의미는 아니다.
