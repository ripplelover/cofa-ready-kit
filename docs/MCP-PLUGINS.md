# 초기 Codex CLI에서 MCP·플러그인 선택하기

[시험 첫 화면](../README.md) · [전체 문서 지도](INDEX.md)

**기본은 README의 시작 요청이다. 이 문서는 MCP 연결이나 플러그인 확인이 필요할 때만 읽는다.** 공개 도구 사용은 가능하지만 제공 Codex·허용 모델, 자료 반출 금지, Computer Use 금지, 후속 서술형 AI 금지 조건은 그대로 적용된다. [참가자 PDF 규칙](RULES.md)

사전 체험에서 사용자가 확인한 것은 **Codex CLI 형태와 MCP 설정의 `mcpServers` 최상위 이름**이다. 실제 버전·플러그인 지원·로컬 서버의 `command`/`args` 필드·원격 HTTP 서버 필드·본 과제에 설정이 유지되는지는 아직 확인하지 못했다. 일반 Codex 지원과 Cofa 지원을 구분한다.

## 1. 처음 보이는 CLI에서 시작하기

일반 터미널이면 다음을 입력한다.

```bash
codex
```

이미 Codex 입력칸이 열려 있으면 다시 실행할 필요 없다. 작업 폴더 신뢰 확인이 나오면 **실제 과제 폴더**인지 확인한다. Codex 입력칸에서 `/status`, `/model`을 각각 입력해 제공 상태·허용 모델을 확인하고 README의 시작 요청을 보낸다. 개인 로그인·API 키·유료 구독을 추가하지 않는다.

MCP·플러그인 지원을 확인할 때만 **일반 터미널**에서 아래 도움말을 본다. 실행 중인 Codex가 있으면 기존 세션을 종료하지 말고 `+`로 별도 터미널을 열 수 있다. [상세 가이드 p.2]

```bash
codex --version
codex mcp --help
codex plugin --help
```

없는 명령이면 해당 기능을 전제로 진행하지 않는다. 기능을 만들려고 Codex를 교체·업데이트하거나 숨은 기능·권한·감독 설정을 변경하지 않는다. Cofa 사용법은 Helper, 반복 장애는 문제 신고로 확인하며 스킬 직접 읽기·기존 CLI 작업은 계속한다.

## 2. 먼저 연결할 MCP: cofa_local

이 키트의 **로컬 검사 도구 6개를 제공하는 서버 하나**다. 별도 모델 호출·계정·API 키·원격 통신 기능이 없다. stdio 연결이므로 Browser의 포트나 `0.0.0.0` 설정은 사용하지 않는다. [도구별 입력과 결과](SETUP.md#4-선택형-로컬-mcp)

**① 실제 과제 폴더의 일반 터미널에서 설정을 만든다.**

```bash
python3 .cofa-kit/scripts/install.py --workspace . --mcp-json
```

Python 3.10+가 필요하다. 제공 환경에서 `python`만 있다면 그 명령을 쓴다. 이 옵션은 설정을 출력하며 설치·연결을 자동 실행하지 않는다.

**② Cofa MCP 탭에 출력된 설정을 추가하고 저장한다.**

생성 결과는 아래 구조다. 아래 경로는 **설명용 자리표시자**이므로 복사하지 말고 ①의 실제 출력을 사용한다.

```json
{
  "mcpServers": {
    "cofa_local": {
      "command": "실제 Python 실행 파일의 절대 경로",
      "args": [
        "-u",
        "실제 과제 폴더/.cofa-kit/scripts/mcp_server.py",
        "--workspace",
        "실제 과제 폴더"
      ]
    }
  }
}
```

입력칸이 `{"mcpServers": {}}`라면 생성된 전체 JSON을 넣는다. 다른 서버가 있으면 **기존 `mcpServers` 안에 `cofa_local`만 추가**한다. `mcpServers`를 두 번 중첩하거나 같은 서버 이름을 중복 작성하지 않는다. 기존 설정은 지우지 않는다. 실제 화면에서 추가로 요구하는 필드는 화면 안내를 따른다.

**③ 제공 Codex에서 실제 도구를 호출한다.**

```text
연결된 cofa_local의 profile_csv 도구를 실제로 호출해
.cofa-kit/examples/defects.csv를 요약해 줘.
호출한 도구 이름과 반환 결과를 알려 줘.
도구가 없거나 실패하면 그대로 알려 주고, CLI 성공을 MCP 성공이라고 하지 마.
```

저장 성공과 실제 연결 성공은 다르다. 지원되는 버전이면 Codex 입력칸의 `/mcp`에서 상태를 확인할 수 있다. 새 도구가 보이지 않으면 제공 환경의 갱신 안내를 따른다. 새 대화가 필요하면 현재 작업을 저장한 뒤 [재개 요청](../prompts/SCENARIO.md#재개할-때)으로 돌아온다. 플랫폼 관리 프로세스를 종료하지 않는다.

## 3. 추가할 가치가 있는 후보

| 후보 | 이 키트의 선택 | 이유·사용 범위 |
| --- | --- | --- |
| **cofa_local** | 기본 선택형 MCP | 로컬 CSV·반도체·키 관계·기록 파일 검사. 같은 기능을 CLI로도 사용 |
| **OpenAI Docs MCP** | 공개 OpenAI/Codex 문서가 실제 필요할 때만 추가 후보 | 인증 없는 공식 문서 검색·읽기. 일반 기술 질의만 전송 |
| Context7 | 시험 기본 구성에서 제외 | 현재 인증 안내와 외부 질의 처리 범위를 함께 고려. 아래 공식 근거 참고 |
| filesystem·Git·추가 shell MCP | 기본 추가하지 않음 | 제공 Codex의 파일·터미널 기능과 중복. 공개 저장소 받기에 GitHub 계정 연결은 불필요 |
| SQLite·Excel 관련 MCP | 실제 SQL/XLSX 과제가 나오면 필요성 판단 | 먼저 제공된 로컬 라이브러리·CLI 사용. 원격 DB·스프레드시트로 시험 자료를 전송하지 않음 |
| GitHub·Drive·배포 서비스 연결 | 시험 작업에 기본 추가하지 않음 | 외부 계정·게시·파일 전송 기능이 이번 기본 흐름에 필요하지 않음 |
| 브라우저 자동화·별도 AI 모델 MCP | 이 키트에서는 사용하지 않음 | UI는 본인이 확인하고 AI는 제공 Codex·허용 모델만 사용 |

Context7 공식 문서는 Codex 연결에 OAuth·API 키 흐름을 안내하며, 개인정보 문서는 질의의 원격 처리와 문서 정렬용 LLM 전달을 설명한다. 이 내부 처리를 주최 측이 어떻게 분류하는지는 확인하지 못했으므로 위반이라고 단정하지 않는다. **기본 추가 대상으로 권하지 않는다는 키트의 판단**이다. 로컬 stdio 실행이나 읽기 전용 표시만으로 외부 전송이 없다고 판단하지 않는다. [Codex 연결 안내](https://context7.com/docs/clients/codex), [데이터 처리](https://context7.com/docs/security/data-privacy)

### OpenAI Docs MCP를 선택했다면

공식 서버는 `https://developers.openai.com/mcp`다. 공개 OpenAI 문서를 읽으며 OpenAI API를 대신 호출하는 도구가 아니다. 서버 이용에 개인 API 키가 필요하지 않다. [공식 Docs MCP](https://developers.openai.com/learn/docs-mcp), [인증 안내](https://developers.openai.com/api/docs/guides/tools-connectors-mcp#authentication)

**원격 서버이므로 검색어·도구 인수는 외부로 전달된다.** 시험 문제·코드·CSV·로그·내부 경로·접속 정보·결과물을 붙이지 않는다. Cofa 화면 조작·시험 규정은 공식 OpenAI 문서에서 추정하지 말고 Cofa Helper와 참가자 안내를 따른다. 이 원격 도구는 기본 시작 요청의 자동 선택 대상에 넣지 않았다.

`mcpServers` 이름만 확인됐다고 HTTP 연결까지 지원되는 것은 아니다. **MCP 탭이 원격 HTTP 서버의 `url` 필드를 지원한다고 안내하는 경우에만** 다음 서버 항목을 기존 `mcpServers` 안에 추가할 수 있다. 아래는 추가할 항목의 예이며 기존 전체 설정을 교체하는 JSON이 아니다.

```json
{
  "openai_docs": {
    "url": "https://developers.openai.com/mcp"
  }
}
```

탭이 이 형식을 지원하지 않으면 임의의 `type` 값·별도 프록시·로그인을 덧붙이지 않는다. 제공 환경이 **CLI 등록 방법을 허용하는 경우에만** 공식 일반 Codex 명령을 대안으로 쓸 수 있다.

```bash
codex mcp add openai_docs --url https://developers.openai.com/mcp
```

연결 후 제공 Codex에 보낼 일반 질의 예:

```text
연결된 openai_docs로 Codex CLI의 MCP 연결 상태 확인 방법을 찾아 줘.
파일·시험 문제·데이터·로그를 읽어서 도구 인수에 넣지 말고,
이 일반 기술 질문만 보내 공식 문서와 현재 환경의 차이를 알려 줘.
```

실제 도구 목록·호출 결과로 연결을 확인한다. 연결되지 않으면 기존 제공 검색 도구나 Cofa Helper로 진행한다. 문서 서버가 없다는 이유로 과제 구현을 멈추지 않는다.

## 4. Codex CLI 플러그인도 사용할 수 있나

**지원하는 Codex CLI에는 플러그인 기능이 있다.** 공식 안내는 Codex 입력칸의 `/plugins`와 일반 터미널의 `codex plugin`을 설명한다. 설치한 지침·도구는 새 세션에서 불러오며 별도 MCP 연결이 필요할 수 있다. [공식 플러그인 안내](https://learn.chatgpt.com/docs/plugins)

하지만 CLI 화면의 외형만으로 Cofa 버전·기능·설치 허용까지 확정할 수는 없다. 먼저 1번의 도움말에서 `plugin` 지원을 확인한다. 지원하고 제공 환경이 안내하는 경우에만 Codex 입력칸에서 `/plugins`를 열거나, 일반 터미널에서 다음을 확인한다.

```bash
codex plugin list --help
codex plugin list --json
```

목록 출력은 설치·연결 완료를 의미하지 않는다. 현재 채팅 앱의 플러그인 목록과 Cofa CLI의 목록도 별개다. 사용하려는 공개 플러그인의 **실제 스킬, 연결 MCP, 실행 훅·스크립트, 인증과 전송 동작**을 살핀다. 문서에 없는 설치 명령을 추정하지 않고 제공 환경의 목록·안내를 따른다. [CLI 명령과 지원 옵션](https://learn.chatgpt.com/docs/cli/reference)

| 플러그인 내용 | 시험에서의 판단 |
| --- | --- |
| 공개 지침·로컬 참조만 제공 | 실제 과제에 필요하고 제공 환경에서 지원하면 검토 가능. 키트의 6개 스킬은 이미 직접 읽을 수 있음 |
| 로컬 MCP를 함께 제공 | 입력·출력·실행 스크립트까지 확인. 로컬 설치가 통신 없음의 증명은 아님 |
| 개인 키·유료 구독·외부 AI가 필요 | 사용하지 않고 제공 도구로 진행 |
| 시험 자료를 외부 계정에 전송·게시하거나 UI를 자동 조작 | 이 키트의 시험 흐름에서 사용하지 않음 |

OpenAI Developers 전체 플러그인은 문서 조회 외에 Platform 연결·프로젝트 키 생성 등 더 넓은 기능을 포함한다. 이 시험을 위해 전체 플러그인을 설치할 이유는 확인하지 못했으며 문서 조회만 필요하다면 위 Docs MCP 후보로 범위를 줄인다. [공식 포함 기능](https://developers.openai.com/learn/developers-codex-plugin)

제공 Codex에 선택 검토만 맡길 때:

```text
먼저 제공된 CLI의 plugin 지원과 현재 목록을 확인해 줘.
과제에 부족한 기능이 실제로 있는 경우에만 공개 플러그인 후보를 검토해 줘.
스킬·MCP·훅·인증·외부 전송 동작과 규칙 충돌 여부를 설명해 줘.
개인 인증·외부 AI·시험 자료 반출·UI 자동 조작은 사용하지 마.
지원되지 않거나 확인이 안 되면 현재 스킬과 로컬 도구로 계속 진행해 줘.
```

이 지시는 설치를 무조건 시작하라는 뜻이 아니다. 현재 구성은 **제공 Codex + 필요한 스킬 직접 읽기 + 선택형 cofa_local**로 진행할 수 있다. 제출 확정 후에는 스킬·MCP·플러그인 사용을 중단하고 후속 서술형은 본인이 답한다.
