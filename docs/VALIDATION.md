# 검증 결과와 남은 범위

검증일: 2026-10-30, 키트 버전 1.2.1. 개발·실행 환경은 Windows, Python 3.10.7, Node 20.9.0이다. 이 기록은 준비 키트의 확인 결과이며 대회 과제의 검증 결과가 아니다.

추가로 [공개 복제본을 이용한 합성 과제 리허설](REHEARSAL-2026-10-30.md)을 실행했다. 해당 과제 자체 10개와 독립 검증 18개가 통과했고, 로컬 Codex가 설치 스킬 5개를 발견했다. Sol 지정 요청은 응답했으나 파일 읽기는 정책에 차단됐다. 아래 키트 테스트 수와 합산하거나 Cofa·Sol의 전체 과제 수행 성공으로 해석하지 않는다.

## 실행한 검사

```text
python -m unittest discover -s tests -v
69 tests: 68 passed, 1 skipped
```

건너뛴 1개는 Windows 계정에서 심볼릭 링크를 만들 권한이 없어 실행하지 못한 경로 이탈 검사다. 다른 경로 이탈·존재하는 외부 파일 접근 거부·파일 보존 검사는 실행했다. 이 환경에서 symlink 방어가 실행 검증됐다고 표시하지 않는다.

확인한 범위:

- 초기화의 덮어쓰기 방지, 빈 요구사항·미완료·없는 근거 파일 실패 판정.
- CSV·JSON 결측·중복·수치 요약과 표본 범위, 잘못된 입력 처리.
- 명령 실패·타임아웃·출력 제한, 테스트 0개·전부 skip 구분, 사용자 선언과 실제 실행 구분.
- 스킬 설치 dry-run, 반복 설치, 충돌 시 사용자 파일과 기존 내용 보존.
- MCP stdio 초기화, 도구 목록, 실제 CSV 분석과 요구사항 검사, 오류 뒤 세션 유지.
- 잘못된 JSON·요청 ID·도구 이름·입력 경로 처리.
- 가중 검사 통과율 손계산, 복합키 중복·결측·비정상 수량·0 분모, 전체 집계의 행 수 한도 처리.
- I-MR 손계산, 감시 데이터에 영향받지 않는 기준 한계, 기준→감시 경계의 이동범위, 상수열·시간순서·혼합 계열 처리.
- 반도체 MCP 두 도구의 실제 CLI 연결과 잘못된 옵션 거부.
- CSV 관계 검사: 복합키·앞자리 0 보존, 전체 키 유일성, 2×3 결합의 예상 6행, 미매칭·0행, 잘못된 CSV·행 제한, 종료코드·출력 보존.
- 새 MCP `csv_join_audit`의 실제 CLI 호출, 관계 위반 진단, 인수·경로 제한. v1.2.0에서 기존 49개에 관련 검사 12개를 추가했다.
- v1.2.1의 로그 보호: 정상 마지막 개행 누락, 다른 형식·깨진 JSON·잘못된 레코드 보존, 명령 실행 전 로그 검사, 추가 기록의 크기 제한.
- Node 기본 TAP의 0개·전부 skip·TODO-only·정상·실패. 실제 `node --test` 실행 검사를 포함하고 해당 검사는 모두 수행했다. Node 부재로 건너뛴 검사는 없다. 이번 로그·Node 회귀 검사 8개를 더해 총 69개다.

v1.2.0의 [조인 실습](DATA-JOIN.md)은 구현을 읽기 전 문서 명령부터 별도 실행했다. CLI 확인 항목 18개, 실제 stdio MCP 확인 항목 11개, 추가 경계 사례 12개가 통과했다. 이는 전체 테스트와 별도의 확인 기록이며 테스트 수에 합산하지 않는다. 합성 원본 해시·출력 보존과 예상 결합 행 수 4/5/5/6이 일치했다. 실제 Cofa MCP 탭 연결이나 업무상 키의 정확성을 검증한 것은 아니다.

다섯 스킬은 OpenAI 제공 `skill-creator/scripts/quick_validate.py`에서 모두 `Skill is valid!` 결과를 얻었다. 검증용 PyYAML은 개발용 제외 폴더에만 설치했으며 배포 키트 실행 의존성이 아니다.

v1.2.1 재점검에서는 README → SCENARIO → 필요한 스킬 직접 읽기의 연결, 제출 확정 후 중단, 실제 과제와 준비 예제의 구분을 독립 검토했다. 기존 코드 수정 참조와 최신순 공개 저장소 11곳의 반영 내역도 확인했다. 로컬 Markdown 링크 대상과 다섯 스킬 형식 검사를 통과했다. 이는 실제 Cofa 모델이 전체 흐름을 수행했다는 증거가 아니다.

배포 ZIP을 새 폴더에 풀어 **26개 확인 항목**을 통과했다. 공개 파일 60개, 선택형 스킬 5개 설치·반복 설치, 새 기존 프로젝트 참조와 설치 후 상대 링크, CLI 버전·환경, 다른 형식 로그 보존·정상 마지막 줄 분리, 실제 Node 0개 테스트 거부, MCP 1.2.1 초기화·도구 5개·CSV 호출을 확인했다. 이 항목 수를 위 69개 테스트에 합산하지 않는다. 개인 PDF·개발용 비공개 폴더·인증 파일은 배포 대상에 없다.

[상세 매뉴얼](MANUAL.md)의 합성 연습 코드블록을 별도 임시 작업 폴더에서 실행했다. 실제 테스트 3개, 검토 전 `check=1`, 검토 후 `check=0`, 보고서 생성과 기존 파일 보호 동작을 확인했다. 반도체 합성 예제의 독립 계산 예상값은 [expected.json](../examples/semiconductor/expected.json)에 있다. 실제 생산 자료나 설비 검증 결과가 아니다.

별도의 합성 상황 검토에서는 triage가 실제 CSV의 중복·결측만 사실로 인정하고 업무 규칙을 실무자에게 확인하도록 정리하는지 확인했다. explain은 이미 제출 확정 후 서술형이 진행 중인 상황에서 답안 작성을 진행하지 않았다. 이 검토는 현재 개발 세션에서의 지침 적용 검토이며, 시험용 Sol 환경의 응답 품질을 실측한 것은 아니다.

반도체 스킬의 별도 사례 검토에서는 TOOL-A/TOOL-B의 관측 통과율 차이를 계산하되, 서로 다른 lot를 검사한 자료만으로 장비 우수성이나 불량 원인을 확정하지 않는지 확인했다. 새 작업 폴더에 다섯 스킬을 설치한 뒤 반도체 스킬의 상대 참조 3개가 모두 설치된 파일로 연결되는 것도 확인했다.

## 아직 검증하지 못한 것

- 실제 Cofa의 OS·Python·Codex 버전, 스킬 자동 탐색, MCP 탭 JSON 스키마와 연결.
- Cofa의 공개 저장소 다운로드 접근 정책, 사전 체험 설정의 본 과제 유지 여부.
- Linux에서의 실행과 Windows에서의 심볼릭 링크 권한 있는 실행.
- 실제 과제의 채점 기준·기능 정확성·성능·진출 가능성.

사전 체험에서 파일 읽기·짧은 CLI·제공 Codex 호출을 먼저 확인한다. 스킬 자동 탐색이 안 되면 직접 파일 읽기, MCP가 안 되면 CLI로 사용할 수 있다.

## 도구의 의도적인 한계

`check`는 파일과 선언 상태의 구조 검사다. 위조된 결과나 부실한 테스트를 의미적으로 판별하지 못한다. `run`의 요약 인식은 일반적인 unittest·pytest와 Node 기본 TAP 출력에 대한 휴리스틱이며 Jest·Vitest·사용자 정의 리포터까지 이해하지 못한다. 인식되지 않으면 `recognized: null`이며 실제 개수·결과를 직접 읽어야 한다. 한 명령에 여러 테스트 실행을 합치기보다 개별 검사로 기록하고 내용을 확인한다.

실행 뒤 소스·입력·설정 변경을 자동 fingerprint로 감지하는 기능은 없다. 마지막 검사 뒤 영향받는 파일을 바꾸거나 작업을 통합했다면 관련 검사를 다시 실행한다. 로그의 형식 보호는 여러 프로세스의 동시 쓰기를 잠금으로 조정하는 기능이 아니므로 같은 로그에 동시에 기록하지 않는다.

`run`은 보안 샌드박스가 아니며, 사용자가 지정한 명령을 실행한다. timeout은 직접 실행한 자식 프로세스까지만 종료한다. 대회에서 허용된 로컬 일회성 검증에 사용한다. 서버·백그라운드 자손 프로세스 실행용으로 사용하지 않는다.

MCP는 직접 작성한 작은 stdio 구현으로, 이 키트의 읽기 전용 도구 다섯 개만 제공한다. 전체 MCP 기능을 구현한 범용 SDK가 아니며 실제 클라이언트 호환성은 별도 확인이 필요하다. 기반 규격: [MCP 수명주기](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [도구](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [stdio 전송](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
