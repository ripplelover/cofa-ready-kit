# 검증 결과와 남은 범위

[시험 첫 화면](../README.md) · [전체 문서 지도](INDEX.md)

최근 검증일: **2026-10-31 KST**, 키트 버전 **1.3.0**. 개발·실행 환경은 Windows, Python 3.10.7, Node 20.9.0이다. 아래 과거 버전의 확인 기록은 날짜·버전을 구분한다. 이 기록은 준비 키트의 확인 결과이며 대회 과제의 검증 결과가 아니다.

추가로 [공개 복제본을 이용한 합성 과제 리허설](REHEARSAL-2026-10-30.md)을 실행했다. 해당 과제 자체 10개와 독립 검증 18개가 통과했고, 로컬 Codex가 설치 스킬 5개를 발견했다. Sol 지정 요청은 응답했으나 파일 읽기는 정책에 차단됐다. 아래 키트 테스트 수와 합산하거나 Cofa·Sol의 전체 과제 수행 성공으로 해석하지 않는다.

## 실행한 검사

```text
python -m unittest discover -s tests -v
89 tests: 87 passed, 2 skipped
```

건너뛴 2개는 Windows 계정에서 심볼릭 링크를 만들 권한이 없어 실행하지 못한 경로 검사다. 다른 경로 이탈·존재하는 외부 파일 접근 거부·파일 보존 검사는 실행했다. 부모 폴더의 재분석 지점 속성을 모의한 검사는 통과했으나 실제 symlink/reparse 생성 검증과 구분한다.

확인한 범위:

- 초기화의 덮어쓰기 방지, 빈 요구사항·미완료·없는 근거 파일 실패 판정.
- CSV·JSON 결측·중복·수치 요약과 표본 범위, 잘못된 입력 처리.
- 명령 실패·타임아웃·출력 제한, 테스트 0개·전부 skip 구분, 사용자 선언과 실제 실행 구분.
- 스킬 설치 dry-run, 반복 설치, 충돌 시 사용자 파일과 기존 내용 보존.
- MCP stdio 초기화, 도구 목록, 실제 CSV 분석과 요구사항 검사, 오류 뒤 세션 유지.
- 잘못된 JSON·요청 ID·도구 이름·입력 경로 처리.
- 가중 검사 통과율 손계산, 복합키 중복·결측·비정상 수량·0 분모, 전체 집계의 행 수 한도 처리.
- I-MR 손계산, 감시 데이터에 영향받지 않는 기준 한계, 기준→감시 경계의 이동범위, 상수열·시간순서·혼합 계열 처리.
- 반도체 MCP 두 도구의 실제 CLI 연결과 잘못된 옵션 거부.
- CSV 관계 검사: 복합키·앞자리 0 보존, 전체 키 유일성, 2×3 결합의 예상 6행, 미매칭·0행, 잘못된 CSV·행 제한, 종료코드·출력 보존.
- 새 MCP `csv_join_audit`의 실제 CLI 호출, 관계 위반 진단, 인수·경로 제한. v1.2.0에서 기존 49개에 관련 검사 12개를 추가했다.
- v1.2.1의 로그 보호: 정상 마지막 개행 누락, 다른 형식·깨진 JSON·잘못된 레코드 보존, 명령 실행 전 로그 검사, 추가 기록의 크기 제한.

문서 정리 후에는 별도 검토자가 README의 다운로드 → 로컬 파일 열기 → Codex 요청 → 스킬 직접 읽기 → 구현·검증·제출 흐름을 읽어 확인했다. 문서 지도 자체를 제외한 공개 Markdown 38개가 모두 [전체 문서 지도](INDEX.md)에 연결되고, 로컬 링크 대상과 README의 새 제목 앵커도 확인했다. 기존 안내의 중복 시작 요청과 오래된 앵커를 정리했다. 실제 시험 화면의 사용성 실측은 아니다.

반도체 스킬의 별도 사례 검토에서는 TOOL-A/TOOL-B의 관측 통과율 차이를 계산하되, 서로 다른 lot를 검사한 자료만으로 장비 우수성이나 불량 원인을 확정하지 않는지 확인했다. 새 작업 폴더에 다섯 스킬을 설치한 뒤 반도체 스킬의 상대 참조 3개가 모두 설치된 파일로 연결되는 것도 확인했다.

## 스킬의 합성 상황 수동 검토

2026-10-31에는 개발 에이전트가 현재 지침을 읽고 다음 네 합성 요청에 실제 응답 초안을 작성해 수동 검토했다. 과제 코드를 실행하거나 제공 Sol을 호출한 검사가 아니므로 “모델 테스트 4개 통과”라고 집계하지 않는다.

| 합성 상황 | 확인한 행동과 수정 |
| --- | --- |
| 기존 API의 `limit=0` 경계 오류 | 기존 계약·최소 수정·재현·회귀 검사를 연결하고 실행하지 않은 API 응답을 관측했다고 쓰지 않음 |
| 재검사 정책·분모가 불분명한 검사 CSV | 확정된 구조 점검을 진행하며 업무 기준은 미확인으로 보류. 채택한 임시 가정과 미응답을 구분하도록 문구 수정 |
| 제출 확정 후 실제 서술형 답 요청 | 답안·개요·관련 분석을 제공하지 않고 본인 답변 단계임을 안내 |
| CSV 자유텍스트에 검사 생략·성공 선언 지시 | 자료와 작업 지시를 구분. 기존 대응이 키트 지침만의 효과라고 볼 수 없어 SCENARIO에 경계를 명시 |

수정된 2·4번은 같은 입력과 행동 기준으로 문구와 응답을 다시 검토했다. 성공률·지연·토큰·모델 간 우열을 측정한 비교가 아니며 일반 모델 지침의 효과와 스킬의 기여를 분리할 수 없다. [참고한 공식 자료와 적용 판단](RESEARCH.md#openai-공식-자료로-재점검한-내용)

새 `cofa-model-eval`은 두 합성 반례에 수동 적용했다. 미래 고장을 예측하면서 사후 수리 결과·전체 자료 스케일링·무작위 분할을 쓰려는 경우에는 예측 시점과 시간·장비 그룹 분리를 확인하도록 정리했다. 1,000건 중 양성이 8건인데 모두 음성으로 예측한 정확도 99.2%는 재현율 0과 함께 해석하고, 최종 테스트에서 임계값을 골랐다면 독립 평가라고 부르지 않도록 했다. 모델을 실제 학습하거나 제공 Sol의 성능을 측정한 검사는 아니다.

규칙 재점검에서는 첨부 PDF 3개 총 7쪽, 스킬·요청문 21개 파일, CLI·MCP·설치·패키징 소스를 대조했다. 공개 추적 파일 66개에 개인 PDF·개발용 비공개 폴더·인증 파일 경로가 들어 있지 않은 것도 확인했다. [규칙 대조 결과와 운영 경계](RULES.md#이-키트와-규칙을-대조한-결과)에 기록했으며, 실제 응시 상황의 준수나 주최 측 개별 승인을 보증하는 검사는 아니다. 이번 수정은 안내 문구이며 실행 코드는 변경하지 않았다.

그 뒤 참가자의 사전 체험 보고인 **초기 CLI·`mcpServers` 이름**을 반영해 [MCP·플러그인 안내](MCP-PLUGINS.md)를 추가했다. 개발 PC의 `codex-cli 0.164.0-alpha.11.1`에서 `mcp`·`plugin` 도움말을 확인했고, 설정 생성기의 실제 Python·서버·작업 경로 및 로컬 서버만 포함하는 출력을 확인했다. JSON 예제 두 개의 구문과 전체 목차의 대상 Markdown 39개 연결도 점검했다. 공식 문서·카탈로그 조회 외에 추가 서버 연결·플러그인 설치·개인 인증·전역 설정 변경은 수행하지 않았다. 코드 변경이 없어 전체 회귀 테스트는 반복하지 않았다. 새 안내 한 파일을 포함한 현재 공개 배포 대상은 67개이며 앞의 66개 ZIP 검사는 당시 배포본 기록이다.

제출 전 작업 정리 기능은 README → SCENARIO → `cofa-explain`에 연결하고 구현·검증 스킬에도 기록 갱신 지침을 넣었다. 변경한 세 스킬의 형식 검사와 로컬 Markdown 링크 검사를 통과했다. 독립 검토자는 합성 기록을 적용해 기존 CSV 로더와 이번 수정, AI 작업과 참가자의 명시적 요청, 수정 전 테스트 통과와 수정 후 미검증, 제안만 한 차트를 구분하는 요약을 작성했다. 제출 확정 뒤 같은 요약을 갱신해 달라는 합성 요청에서는 작업을 중단했다. 이는 개발 세션의 지침 적용 검토이며 실제 Cofa·제공 모델에서 자동 요약이 실행됐다는 증거가 아니다. 실행 코드 변경이 없어 전체 회귀 테스트는 반복하지 않았다.

여러 도구의 자동 선택은 README 시작 요청과 SCENARIO의 과제별 선택 표에 연결했다. 별도 검토자가 CSV 없는 API 수정, 키·관계 미확정 CSV, 공개 Codex 문서 조회, 제출 확정 후 요약 요청 네 합성 상황에 지침을 적용했다. 불필요한 MCP 미호출, 업무 기준 의존 호출 보류와 독립 구조 확인 지속, 원격 질의에서 시험 자료 제외, 확정 후 중단을 확인했다. 문서 링크와 JSON 예제도 점검했다. 이는 개발 세션의 지침 적용 검토이며 실제 Cofa 도구 선택·원격 연결 검사가 아니다. 새 옵션은 설정 후보를 출력할 뿐이고 이번 검증에서 외부 서버 연결·플러그인 설치·전역 설정 변경은 하지 않았다.

## 아직 검증하지 못한 것

- 실제 Cofa의 OS·Python·Codex 버전, 스킬 자동 탐색, MCP 탭의 세부 JSON 필드와 연결·플러그인 지원. 최상위 `mcpServers` 이름은 참가자의 사전 체험 보고로만 확인했다.
- Cofa의 공개 저장소 다운로드 접근 정책, 사전 체험 설정의 본 과제 유지 여부.
- Linux에서의 실행과 Windows에서의 심볼릭 링크 권한 있는 실행.
- 실제 과제의 채점 기준·기능 정확성·성능·진출 가능성.

사전 체험에서 파일 읽기·짧은 CLI·제공 Codex 호출을 먼저 확인한다. 스킬 자동 탐색이 안 되면 직접 파일 읽기, MCP가 안 되면 CLI로 사용할 수 있다.

## 도구의 의도적인 한계

`check`는 파일과 선언 상태의 구조 검사다. 위조된 결과나 부실한 테스트를 의미적으로 판별하지 못한다. `run`의 요약 인식은 일반적인 unittest·pytest와 Node 기본 TAP 출력에 대한 휴리스틱이며 Jest·Vitest·사용자 정의 리포터까지 이해하지 못한다. 인식되지 않으면 `recognized: null`이며 실제 개수·결과를 직접 읽어야 한다. 한 명령에 여러 테스트 실행을 합치기보다 개별 검사로 기록하고 내용을 확인한다.

요약은 각 스트림 끝부분 16,384바이트에서만 찾으며, 여러 완전한 요약을 찾으면 `ambiguous: true`로 자동 성공을 막는다. 이 구간 밖의 실패 요약을 모두 탐지하거나 전체 출력을 보존하지는 않는다. 실제 판정에 쓴 `*.tail.txt`와 바이트 범위는 기록한다. 출력 제한은 앞부분 제한에 tail 합계 최대 32,768바이트가 추가되는 방식이다.

v1.3.0의 `run --watch`는 직접 선택한 기존 파일의 실행 전후 내용을 기록한다. 이후 `evidence check` 또는 `evidence_freshness`를 호출해야 현재 내용과 비교한다. 최대 32개·각 읽기 단계 총 32MiB이며 지정하지 않은 의존성·환경 변화, 관측 사이에 변경됐다가 복원된 변화, 위조한 기록은 탐지하지 못한다. `fresh: true`도 테스트 통과나 요구사항 충족을 뜻하지 않는다. `check`·`report`가 이 비교를 자동 수행하지 않으며 영향받는 변경·통합 뒤 실제 검사는 다시 실행한다. 로그 형식 보호는 동시 쓰기 잠금이 아니므로 같은 로그에 동시에 기록하지 않는다.

`run`은 보안 샌드박스가 아니며, 사용자가 지정한 명령을 실행한다. timeout은 직접 실행한 자식 프로세스까지만 종료한다. 대회에서 허용된 로컬 일회성 검증에 사용한다. 서버·백그라운드 자손 프로세스 실행용으로 사용하지 않는다.

MCP는 직접 작성한 작은 stdio 구현으로, 이 키트의 읽기 전용 도구 여섯 개만 제공한다. 전체 MCP 기능을 구현한 범용 SDK가 아니며 실제 클라이언트 호환성은 별도 확인이 필요하다. 기반 규격: [MCP 수명주기](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [도구](https://modelcontextprotocol.io/specification/2025-11-25/server/tools), [stdio 전송](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).
