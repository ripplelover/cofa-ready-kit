# 처음 쓰는 사람을 위한 여러 스킬 사용법

> 시험 첫 화면: [README](../README.md) · 전체 문서 목차: [INDEX](INDEX.md)

**상세 참고가 필요할 때만 읽는 문서다. 시작은 README 한 곳에서 한다.** 아래는 스킬을 이름으로 호출하고 싶은 사람을 위한 선택형 설치·조합 설명이다. 이 문서의 예시는 대회 전 연습 또는 과제 제출 확정 전 작업용이다.

기본 진행은 [README](../README.md)의 다운로드 → 파일 열기 → 시작 요청 순서다. Codex가 필요한 스킬 파일을 직접 읽으므로 설치·이름 암기가 필요하지 않다. 이름으로 호출하려면 아래 설치 절차를 마친 후 같은 Codex 대화에서 필요한 스킬 이름과 할 일을 적는다. 처음에는 한 단계씩 결과를 확인하고 익숙해지면 관련 있는 두 스킬을 함께 요청할 수 있다. [진행·제출 상세 참고](EXAM-PLAYBOOK.md)에 화면 위치와 확인 순서가 있다.

## 1. 먼저 네 가지를 구분하기

| 이름 | 하는 일 | 이 키트의 예 |
| --- | --- | --- |
| Codex와 모델 | 요청을 읽고 파일을 살피고 작업하는 AI | 제공 Codex에서 허용된 Sol 선택 |
| Skill | AI가 작업할 때 읽는 지침과 참고 자료 | `cofa-triage`의 문제 정의 절차 |
| CLI | 터미널에 명령을 입력해서 실행하는 프로그램 | `python3 .cofa-kit/scripts/cofa.py doctor` |
| MCP | AI가 이름으로 호출할 수 있도록 도구를 연결하는 방식 | 로컬 CSV 요약 도구 호출 |

스킬을 6개 설치하면 6개의 작업 지침이 준비된다. 필요한 스킬이 선택될 때 해당 지침을 읽는다. 모든 스킬이 계속 실행되거나, 설치만으로 과제가 완성되는 것은 아니다. 이 키트의 스킬은 MCP 연결 없이도 사용할 수 있다.

두 스킬을 지정하는 요청은 기본적으로 **한 Codex 대화에서 두 지침을 함께 적용**하도록 요청하는 것이다. 여러 에이전트가 작업을 나눠 수행하는 병렬 실행은 별도 기능이며 이 사용법에 필요하지 않다.

Codex CLI의 `/skills`와 `$`를 통한 명시적 호출, 요청에 맞는 자동 선택, `.agents/skills` 탐색은 [OpenAI 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)에 설명되어 있다. 아래 조합과 작업 순서는 이 키트의 사용 예다. 실제 Cofa 제공 버전에서 목록과 파일 접근이 되는지는 사전 체험으로 확인한다.

## 2. 어디에 입력할지 구분하기

| 지금 보고 있는 곳 | 입력 예 |
| --- | --- |
| 일반 터미널: 프로그램 명령을 실행하는 칸 | `git clone ...`, `python3 ...`, `codex` |
| `codex` 실행 후 나타나는 AI 대화 입력란 | `/status`, `/model`, `/skills`, `$cofa-triage`, 자연어 요청 |

**`$cofa-triage`를 일반 PowerShell이나 Bash에 직접 입력하지 않는다.** 셸이 `$`를 변수로 해석할 수 있다. 먼저 터미널에서 `codex`를 실행하고 AI 입력란에 넣는다. 아래 코드블록의 `bash`, `text` 같은 표시는 설명용이며 입력하지 않는다. 블록 안의 내용만 사용한다.

문서의 경로에서 `/`는 폴더 구분이고 `.cofa-kit`은 공개 키트를 받은 폴더 이름이다. `--workspace .`의 마지막 점은 **현재 폴더를 작업 대상으로 지정한다**는 뜻이다. 이 설치기는 지정한 폴더의 `.agents/skills`에 스킬을 복사한다.

## 3. 이름으로 호출하려고 직접 설치할 경우

이 절은 **Cofa 제공 작업 공간의 일반 터미널**에서 수행한다. 아래 예는 Bash 계열이다. 오늘 개인 PC에서 연습하는 절차는 [상세 매뉴얼 2–3장](MANUAL.md)을 참고한다. 개인 PC의 설치가 시험 당일 작업 공간으로 자동 이전된다고 가정하지 않는다.

**① 현재 위치를 확인한다.**

```bash
pwd
ls -la
```

과제 README와 제공 파일이 있는 폴더인지 확인한다. 위치를 모르겠으면 제공 Codex에 현재 경로와 과제 파일 위치부터 확인해 달라고 요청한다. 추측한 폴더로 이동하지 않는다.

**② 공개 키트를 받는다.** `.cofa-kit`이 아직 없을 때 한 번 실행한다.

```bash
git clone --depth 1 https://github.com/ripplelover/cofa-ready-kit.git .cofa-kit
```

명령이 완료되면 현재 과제 폴더 안에 `.cofa-kit`이 생긴다. **그 안으로 `cd`하지 않고 과제 폴더에 그대로 머문다.** 그래야 다음 설치 대상이 과제 폴더가 된다. 이미 `.cofa-kit`이 있다면 재복제하지 말고 [업데이트·충돌 처리](MANUAL.md#4-3-cofa-kit이-이미-있는-경우)를 따른다.

**③ Python이 실행되는지 확인한다.**

```bash
python3 --version
```

3.10 이상이 출력되면 다음으로 간다. 명령이 없거나 실패하거나 버전이 낮으면 `python --version`을 확인한다. 이 명령이 성공하고 **3.10 이상일 때** 아래의 `python3`을 모두 `python`으로 바꾼다. 이 PC의 리허설에서는 실제로 `python`만 성공했다. 둘 다 사용할 수 없거나 둘 다 3.10 미만이면 설치 도구 대신 8장의 스킬 파일 직접 읽기를 사용한다.

**④ 스킬을 설치한다.**

```bash
python3 .cofa-kit/scripts/install.py --workspace .
```

출력에 `cofa-build`, `cofa-explain`, `cofa-model-eval`, `cofa-semiconductor`, `cofa-triage`, `cofa-verify`가 나오면 복사 결과를 확인한다. `copy`는 새 복사, `already present`는 같은 내용이 이미 있다는 뜻이다. 여섯 스킬을 각각 설치할 필요는 없다. 저장 위치는 현재 폴더의 `.agents/skills/`다. 기존 스킬 내용이 다르다는 오류가 나면 지우거나 덮어쓰지 말고 8장의 직접 읽기를 사용한다.

**⑤ 실행 환경을 확인한다.**

```bash
python3 .cofa-kit/scripts/cofa.py doctor
```

`python_supported: true`와 버전 정보를 확인한다. 이는 로컬 실행 프로그램의 확인이며 실제 모델 응답이나 Cofa 연결 성공을 뜻하지 않는다.

**⑥ 제공 Codex를 연다.**

```bash
codex
```

이제부터는 **Codex의 AI 입력란**이다. 아래는 한 번에 붙여 넣는 블록이 아니라 각각 입력해 확인할 명령이다.

- `/status`: 현재 세션 정보를 확인한다.
- `/model`: 실제 제공 목록에서 허용된 모델을 고른다. 안내에 있는 Sol 6.1이 제공되면 시작점으로 사용할 수 있다.
- `/skills`: 사용 가능한 스킬 목록을 확인한다. `$`를 입력해 스킬 선택 목록을 열 수도 있다.

이름이 보이면 해당 스킬을 선택하거나 `$cofa-triage`처럼 요청에 적는다. 목록이 보이지 않으면 8장으로 간다. 스킬을 사용하기 위해 모델을 바꾸거나 개인 로그인·API 키를 넣을 필요는 없다.

## 4. 스킬별 역할을 한 번 확인하기

| 스킬 | 쉬운 설명 | 쓰는 시점 | 결과에서 볼 것 |
| --- | --- | --- | --- |
| `$cofa-triage` | 무엇을 만들어야 하는지 정리 | 처음 README를 읽을 때 | 목표·필수 파일·완료 기준·중요 질문 |
| `$cofa-semiconductor` | 반도체 데이터의 의미와 계산 기준 확인 | 실제 반도체 자료가 있을 때 | 한 행의 의미·분모·재검사·단위 |
| `$cofa-model-eval` | 예측 모델을 올바르게 평가 | 실제 분류·회귀 학습/평가 과제일 때 | 예측 시점·분할·누수·기준선·실제 지표 |
| `$cofa-build` | 확인한 요구사항을 구현 | 중요한 조건이 정해졌을 때 | 수정한 파일·실제 실행 결과 |
| `$cofa-verify` | 요구대로 동작하는지 검사 | 기능 구현 후와 제출 전 | 성공·실패 사례·누락·미검증 |
| `$cofa-explain` | 본인이 만든 것을 설명하는 연습 | 시험 전 또는 제출 확정 전만 | 본인이 먼저 답하고 근거를 점검 |

스킬 이름만 보내기보다 **스킬 이름 + 이번에 할 일 + 확인할 결과**를 적으면 의도가 명확하다. 다음 요청들은 같은 대화에 이어서 보낸다. 단계마다 새 Codex 창을 만들 필요는 없다.

## 5. 이름으로 호출할 때: 한 단계씩 사용하기

아래 블록은 전부 **Codex 입력란**에 보낸다. 첫 블록의 결과를 확인한 뒤 다음 블록을 보낸다. 응답이 끝나거나 입력을 요청할 때까지 기다린다.

**① 문제 파악**

```text
$cofa-triage
현재 과제 README와 제공 파일을 읽어 줘.
누가 어떤 문제를 해결하려는지, 필수 기능과 제출 파일, 완료 기준을 정리해 줘.
명시된 사실과 가정을 구분하고, 답에 따라 구현이 달라지는 질문만 알려 줘.
업무 질문은 내가 실무자에게 직접 전달할게. 확정된 부분의 조사는 진행해 줘.
```

답변에서 필수 파일과 목표가 실제 README와 같은지 확인한다. 중요한 질문이 있으면 플랫폼 실무자에게 직접 물은 다음 **실제로 받은 답**을 Codex에 전달한다. 실무자 답변이 없는 부분을 확인된 사실로 바꾸지 않는다.

**② 반도체 자료라면 데이터 기준 확인**

```text
$cofa-semiconductor
실제 제공 데이터에서 한 행이 무엇인지, 개체 식별자와 검사 단계가 무엇인지 확인해 줘.
통과율의 분모, 재검사 선택, 중복·결측 처리, 단위와 시간 기준을 점검해 줘.
모호한 기준은 확인할 질문으로 남기고, 이 과제에 필요 없는 분석은 추가하지 마.
```

반도체 자료가 없는 과제라면 이 단계를 건너뛴다. 예제의 열 이름이나 재검사 규칙을 실제 데이터에 강제로 적용하지 않는다.

분류·회귀 예측 모델을 만들어야 한다면 이 시점에 [모델 평가 요청](../prompts/MODEL-EVAL.md)을 사용한다. 단순 집계나 화면 구현이면 모델 스킬은 건너뛴다. 반도체 도메인 기준과 모델 평가가 둘 다 필요하면 `$cofa-semiconductor $cofa-model-eval`을 같은 요청에 쓰고 도메인 기준 확인 → 분할·평가 설계 순서를 지정할 수 있다.

**③ 핵심 기능 구현**

```text
$cofa-build
지금 확인된 필수조건 중 가장 중요한 입력부터 결과까지의 흐름을 구현해 줘.
기존 프로젝트의 기술과 실행법을 먼저 확인하고 필요한 파일만 수정해 줘.
완료하면 해당 기능을 실제로 실행하고, 바꾼 파일과 관찰한 결과를 알려 줘.
```

“구현했다”는 말과 실제 파일·명령 결과를 함께 확인한다. 웹 화면이 필요하면 본인이 플랫폼 Browser에서 동작을 확인한다.

**④ 검증**

```text
$cofa-verify
실제 README의 조건과 현재 구현을 비교해 줘.
정상 입력과 중요한 잘못된 입력을 실행하고 기대값과 실제값을 비교해 줘.
필수 파일 누락, 실패한 조건, 아직 검사하지 못한 것을 구분해 줘.
내가 직접 화면에서 확인할 항목도 알려 줘.
```

실패가 있으면 실제 오류를 바탕으로 `$cofa-build`를 다시 요청하고 관련 검사를 실행한다. 아직 검사하지 않은 항목을 완료로 바꾸지 않는다.

**⑤ 제출 확정 전 설명 연습**

```text
$cofa-explain
지금은 제출 확정 전의 이해도 연습이야.
실제 구현에서 중요한 선택을 한 번에 하나씩 질문해 줘.
내가 먼저 답한 다음, 코드와 실행 기록에 맞는지 피드백해 줘.
```

본인이 먼저 답한다. **실제 제출물을 확정한 뒤의 후속 서술형에서는 AI·Skill·MCP를 사용하지 않는다.** 서술형 답안이나 초안을 미리 대신 쓰게 하는 요청이 아니다.

## 6. 두 스킬을 한 요청에서 함께 쓰기

관련 있는 이름 두 개와 각 역할·순서를 함께 적는다. 두 이름은 같은 줄에 적어도 되고 줄을 나눠도 된다. 아래는 복사하기 쉬운 요청 예시이며 별도의 셸 문법이나 자동 병렬 실행 명령이 아니다.

제공 버전에서 두 이름이 모두 인식되는지 확인한다. 한 이름만 인식되거나 적용 여부가 불명확하면 8장처럼 두 `SKILL.md` 파일을 직접 읽게 한다.

**문제 파악 + 반도체 기준 확인**

```text
$cofa-triage $cofa-semiconductor
먼저 README에서 사용자 문제, 필수 제출물, 완료 기준을 정리해 줘.
그다음 실제 반도체 자료의 행 단위, 분모, 재검사 규칙을 검토해 줘.
두 작업을 이 순서로 진행하고, 중요한 미확정 질문만 모아 줘.
```

**구현 + 바로 검증**

```text
$cofa-build $cofa-verify
지금 합의한 가장 중요한 미완료 필수조건 하나를 구현해 줘.
구현 후 그 조건의 정상 입력과 경계·오류 입력을 실제로 검사해 줘.
실패하면 원인을 확인해 최소 수정하고 관련 검사만 다시 실행해 줘.
수정한 파일, 실행 명령, 실제 결과, 남은 미검증을 알려 줘.
```

이 요청은 구현과 검사 순서를 알려 준다. 테스트가 끝나기 전 성공을 보장하지 않는다. 두 스킬 이름이 보인다는 사실보다 결과 파일과 실제 검사 기록을 확인한다.

여섯 스킬은 단계와 과제에 맞춰 사용한다. 특히 `explain`은 구현을 설명할 시점에 따로 호출하면 목적이 분명하다. 새로운 단계나 새 대화에서는 사용할 이름을 다시 적어 준다. 설치나 이전 호출만으로 모든 후속 메시지에 같은 스킬이 계속 적용된다고 가정하지 않는다.

## 7. 스킬 선택을 Codex에 맡기는 요청

매번 이름을 고르기 어렵다면 시작할 때 아래처럼 요청할 수 있다. 이는 작업 방식에 대한 요청이며 플랫폼 설정 변경이나 실행 성공 보장이 아니다.

```text
이 과제에서는 설치된 cofa 스킬을 단계에 맞게 사용해 줘.
먼저 cofa-triage로 요구사항을 정리하고,
실제 반도체 자료가 있으면 cofa-semiconductor로 데이터 기준을 확인해 줘.
예측 모델의 학습·평가가 실제 요구되면 cofa-model-eval로 분할·기준선·지표를 확인해 줘.
확정된 요구사항은 cofa-build로 구현하고 cofa-verify로 검증해 줘.
중요한 업무 기준이 불명확하면 질문을 정리하고 확정된 부분부터 진행해 줘.
각 단계에서 사용한 스킬과 실제로 확인한 결과를 짧게 알려 줘.
설명 연습은 내가 제출 확정 전에 따로 요청할게.
```

처음에는 5장의 단계별 요청으로 결과를 익힌 뒤 이 방식을 사용하면 진행 상황을 이해하기 쉽다.

## 8. 스킬이 목록에 안 나오거나 설치가 막히면

먼저 Codex를 과제 폴더에서 열었는지 확인한다. 자동 탐색을 오래 고치기보다 **공개 키트의 실제 파일을 읽어 적용하도록 요청**할 수 있다.

```text
.cofa-kit/skills/cofa-triage/SKILL.md와
.cofa-kit/skills/cofa-semiconductor/SKILL.md를 읽어 줘.
먼저 과제 요구사항을 정리한 뒤 실제 반도체 자료에 맞는 데이터 기준을 검토해 줘.
참고 파일이 필요하면 각 스킬 폴더 기준의 상대 경로로 읽어 줘.
읽지 못한 파일은 읽었다고 하지 말고 이유와 가능한 다음 작업을 알려 줘.
```

구현·검증도 같은 방식이다.

```text
.cofa-kit/skills/cofa-build/SKILL.md와
.cofa-kit/skills/cofa-verify/SKILL.md를 읽고,
현재 합의한 필수조건에 구현 → 실제 검증 순서로 적용해 줘.
```

이 방법은 파일의 지침을 활용하는 대안이다. 자동 스킬 목록에 등록됐다는 뜻은 아니다. `.cofa-kit-v2`처럼 다른 이름으로 받았다면 경로도 그 이름으로 바꾼다. 공개 키트 자체를 받지 못했다면 해당 파일도 없으므로 읽었다고 가정하지 않는다.

파일 읽기나 명령 실행 자체가 정책에 막히면 오류를 확인하고 Cofa Helper 또는 문제 신고로 문의한다. 스킬 사용을 위해 인증·감독·실행 정책을 변경하지 않는다. [로컬 리허설](REHEARSAL-2026-10-30.md)에서도 스킬 발견과 모델 응답 성공이 파일 실행 성공까지 보장하지는 않았다.

## 9. 두 사용 방식의 차이

```text
기본: README에서 다운로드 → 파일 열기 → 제공 Codex에 시작 요청 → 필요한 스킬 파일 직접 읽기
선택형 이름 호출: 일반 터미널에서 키트 받기·설치 → Codex에서 /skills 확인
이름 호출 예: triage → semiconductor(해당 시) → build → verify
제출 확정 전: 본인 설명 연습
실제 후속 서술형: AI 없이 직접 답변
```

둘 중 한 방식이면 충분하다. 시간이 짧으면 기본 흐름과 실제 실행 결과 확인부터 익힌다. 더 자세한 명령과 기록은 [전체 매뉴얼](MANUAL.md), [반도체 실행 실습](SEMICONDUCTOR-WALKTHROUGH.md)을 참고한다.
