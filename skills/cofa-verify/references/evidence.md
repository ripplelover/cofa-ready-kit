# 검증 기록이 현재 파일에 해당하는지 확인

키트의 `run`으로 실제 검사를 기록하며 코드·테스트·작은 입력 파일의 변경을 추적할 때만 사용한다. 기존 프로젝트에 새 manifest·로그·MCP 연결을 강제하지 않는다. 키트 실행기가 없으면 기존 기록과 변경 파일을 확인하고 영향받는 검사를 다시 실행한다.

- `run`의 명령 구분자 `--` 앞에서 `--watch 상대경로`를 반복한다. 경로는 `--workspace` 기준이며 검증할 기존 일반 파일을 직접 선택한다. 최대 32개, 총 32MiB다.
- 기존에 실제로 정한 요구사항 ID와 일회성 검사 명령을 쓴다. `requirements.json`의 예시 조건을 공식 요구로 취급하지 않는다. 자동 생성되는 출력·로그·캐시 대신 검사의 근거가 되는 코드·테스트·입력을 선택한다.
- 기록의 `watched_files`에는 실행 전후의 파일 내용 해시가 들어간다. 실행 중 변경·누락·불안정이 관측되면 성공으로 처리하지 않는다. 처음부터 없는 파일이나 잘못된 옵션은 입력 오류다.
- 이후 CLI `evidence check --workspace . --result 실행기록의상대경로` 또는 같은 로컬 서버의 `evidence_freshness`에 `result_path`를 전달한다. 새 모델·원격 서비스는 필요하지 않다.
- **파일 동일성과 실행 성공은 별개다.** 실패한 검사의 파일도 그대로일 수 있으므로 비교 결과와 기록의 `execution_ok`, 실제 요구사항·출력 내용을 함께 확인한다. CLI 0만 보고 기능 완료로 선언하지 않는다.
- CLI 1은 변경·누락·실행 중 변화 등을 발견했다는 뜻이다. 영향받는 실제 검사를 새로 실행한다. CLI 2는 추적이 없거나 형식·경로 등 입력이 잘못됐다는 뜻이며 정상 판정이 아니다.
- 결과 파일을 편집해 통과 상태로 만들지 않는다. 이 비교는 암호학적 서명이나 위조 방지 기능이 아니다. 지정하지 않은 파일, 시스템·패키지·외부 상태, 검사 사이에 바뀌었다가 되돌아온 모든 변화까지 증명하지 않는다.

명령을 사용하려면 현재 키트의 `scripts/cofa.py` 경로를 확인한다. `.cofa-kit`으로 받았고 Python 명령이 `python3`인 경우의 접두사는 `python3 .cofa-kit/scripts/cofa.py`다. 서술형 단계가 아니라 제출 확정 전 작업에서만 사용한다.
