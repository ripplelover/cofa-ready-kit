# 과제를 실행 가능한 기준으로 바꾸기

현재 응시 환경에 제공된 README·과제 안내·데이터를 먼저 읽는다. 과제 유형이나 제출 파일명을 준비 키트의 예시로 추정하지 않는다. 이 스킬은 문제 파악을 돕는 지침이며 실제 과제의 요구사항을 대체하지 않는다.

제출 확정 전용이다. 확정 후에는 질문 준비 대기 중에도 이 스킬과 AI 작업을 중단한다.

## 확인할 것

- **사용자와 결정:** 누가 어떤 상황에서 결과물을 쓰며, 무엇을 판단하거나 수행해야 하는가?
- **입력과 출력:** 제공된 파일·스키마·단위·기간, 기대하는 결과와 필수 경로는 무엇인가?
- **기존 프로젝트:** 새로 만드는 과제인지 기존 결함을 고치는 과제인지 구분한다. 기존 실행법·테스트·API/함수 계약·보존해야 할 정상 동작을 확인한다. 수정 과제에 새 앱 제작 계획을 강제하지 않는다.
- **성공 기준:** 필수 기능과 제약을 실제 관찰 가능한 결과로 바꾼다. 예를 들어 “정확한 통계”만 기록하지 말고 집계 단위, 분모, 결측 처리와 작은 수작업 대조 사례를 정한다.
- **평가와 제출:** 명시된 기준, 필수 문서, 실행법, 제출 절차를 찾아 출처 위치와 함께 기록한다. 공개되지 않은 배점은 만들어내지 않는다.

각 요구사항을 `요구사항 → 출처 → 확인 방법 → 구현/검증 상태`로 연결한다. 명시된 조건, 실무자 답변, 작업상 가정을 구분한다. 표는 기존 계획 문서나 키트의 manifest 중 한 곳을 기준으로 관리하여 서로 다른 두 목록을 만들지 않는다.

## 모호함을 줄이는 질문

질문은 **답변에 따라 구현이나 검증이 달라지는 것**부터 선택한다. 우선순위는 대략 `오해할 때 손실 × 영향 범위 ÷ 확인 비용`으로 판단하되 숫자를 지어내지 않는다. 이미 README에 있는 내용을 다시 묻기보다 충돌·누락·경계 사례를 확인한다.

질문을 짧게 작성하고, 가능하면 선택지와 선택에 따른 차이를 붙인다. 업무 맥락 질문은 참가자가 플랫폼의 실무자 에이전트에 직접 전달하게 한다. AI가 메신저를 자동 조작하거나 보낸 것으로 가장하지 않는다. 답변을 기다리면서 확정된 입력 구조 점검 등 독립된 일을 진행한다. 답이 없으면 영향이 작은 가정을 표시하고 되돌리기 쉬운 선택을 한다. 필수조건이 충돌하면 임의로 둘 다 충족했다고 기록하지 않는다.

도움의 종류를 구분한다. 사용법·제출 절차는 Cofa Helper, 접속 장애·반복 오류는 문제 신고, 업무 요구는 실무자 에이전트의 영역이다.

답변이 불완전하면 실제로 답한 범위만 확정한다. 미응답은 미확인으로 남기고, 진행을 위해 실제로 선택한 임시 가정은 따로 표시한다. 결과를 바꾸는 경계 사례로 좁혀 다시 질문한다. 답을 받았다는 사실만으로 관련된 모든 기준이 해결됐다고 기록하지 않는다.

## 마칠 때 남길 내용

문제 정의 한 문단, 필수 요구사항과 검증 방법, 미해결 가정, 먼저 완성할 최소 흐름을 남긴다. 첫 구현은 실제 입력 하나가 의미 있는 결과 하나로 이어지도록 정한다. 자료 분석·알고리즘·보고서 과제라면 웹앱을 추가할 이유가 없다. 남은 시간에 비해 계획이 크면 부가 기능부터 뺀다.

## 응시 환경의 경계

과제 수행은 제공된 Codex와 허용 모델에서 진행한다. 외부 검색이나 원격 MCP 등 외부 서비스에 문제·데이터·코드·결과물을 보내지 않는다. 필요한 공개 문서를 찾을 때도 과제 내용을 포함하지 않는 일반적인 기술 질의만 사용한다. 공개 자료를 가져올 수 있다는 사실이 외부 전송이나 별도 AI 사용을 허용하는 것은 아니다. 감독·플랫폼 설정은 변경하지 않는다. 제출 확정 후에는 이 스킬을 사용하지 않는다.
