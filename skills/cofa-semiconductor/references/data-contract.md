# 데이터 계약: 같은 개체를 같은 기준으로 세기

아래 키와 숫자는 준비용 예시다. 실제 과제의 데이터 사전과 실무자 확인이 우선한다.

## 행 단위와 식별 키

| 한 행의 의미 후보 | 확인할 키 후보 | 흔한 오류 |
| --- | --- | --- |
| lot 한 번의 공정 통과 | lot, operation, route/recipe version, pass/run | 재작업으로 같은 공정을 다시 거친 기록 삭제 |
| wafer 한 번의 검사 집계 | lot, wafer, test stage, test run | `wafer_id`가 lot마다 재사용되는데 전역 유일로 취급 |
| die 하나의 검사 결과 | lot, wafer, die 좌표 또는 die ID, test stage, attempt | 동일 die의 재검사를 별도 제품으로 계산 |
| 결함 한 건 | 검사 run, wafer/die, defect ID 또는 위치, category | 한 die의 여러 결함을 여러 불량 die로 계산 |
| 설비 센서 한 관측 | tool, chamber, recipe, metric, timestamp, sequence | 동시 센서·챔버 관측을 하나의 시계열로 이어 붙임 |

“lot에 항상 몇 장이 들어간다”, “wafer ID는 전역 유일하다” 같은 전제는 두지 않는다. 식별자의 앞자리 0을 보존하고 키 결측·동일 키의 값 충돌을 확인한다. 공정 재진입, 검사 프로그램 변경, 수리 전후는 정상적인 반복 기록일 수 있다.

## 분자·분모를 먼저 문장으로 쓰기

예: “이 제품·검사 단계·기간에 최종 판정이 있는 서로 다른 검사 대상 중 통과한 대상의 비율.” 먼저 단위를 die인지 wafer인지 정한다. 대기·미검사·중단·재검사를 포함하는지 확인한다. 그 다음 컬럼을 매핑한다.

```text
통과율 = 합산 통과 개체 수 / 같은 모집단의 합산 검사 개체 수
불량 개체 비율 = 불량 개체 수 / 검사 개체 수
개체당 결함 수 = 결함 사건 수 / 검사 개체 수
```

셋은 같은 지표가 아니다. NIST는 개체의 적합/부적합 분류와 결함 건수 계수를 구분한다. 하나의 개체에서 여러 결함이 관찰될 수 있으므로 결함 건수가 검사 개체 수보다 커도 모순은 아니다. `p` 계열은 개체 비율, `c/u` 계열은 결함 건수·단위당 건수와 관련된다. [NIST Attributes Control Charts](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc33.htm)

Samsung의 EDS 설명은 웨이퍼 수준 검사·수리·최종 검사와 양품 die 기준 수율을 다룬다. 따라서 키트가 계산하는 `passed/tested`는 우선 **선택된 검사 모집단의 통과율**이다. `tested`가 전체 대상인지 확인하기 전에는 전체 웨이퍼 수율·최종 출하 수율로 확대하지 않는다. [Samsung EDS](https://semiconductor.samsung.com/support/tools-resources/fabrication-process/eight-essential-semiconductor-fabrication-processes-part-8-eds-electrical-die-sorting-for-the-perfect-chips/)

### 손계산으로 잡을 오류

가상 예시 A: W1은 10개 검사·9개 통과, W2는 90개 검사·45개 통과다. 합산은 `54/100 = 54%`. 행별 비율 평균 `(90%+50%)/2 = 70%`는 “웨이퍼별 비율의 동일 가중 평균”이라는 다른 통계다. 전자를 요구받고 후자를 내지 않는다.

가상 예시 B: 4개 die 중 2개에 총 5건의 결함이 있다. 불량 die 비율은 `2/4`, 결함 빈도는 `5/4`건/die다. 이 정보만으로 `1 - 5/4`를 수율이라고 쓰지 않는다. 최종 통과 판정이 따로 있다면 그 판정 기준을 확인한다.

검증에 정상 집계뿐 아니라 `tested=0`, 검사 수 결측, 음수·비정수 수량, `passed>tested`, 같은 키의 상충 기록을 넣는다. 분모 없는 결과는 0%와 구분한다. 서로 다른 제품 구성·기간의 합계 비교는 구성 변화의 영향도 함께 살핀다.

## 재검사와 수리 이력

먼저 “최초 검사 통과율인가, 승인된 최종 판정 통과율인가”를 확인한다. 모든 검사 시도를 합친 값은 검사 이벤트 통과율이며 고유 제품 통과율과 다르다. 마지막 시간값이 항상 승인된 최종 결과라는 보장도 없다.

가상 사례: A는 1차 실패·2차 통과, B는 1차 통과, C는 1차 실패. 세 개체를 모두 관찰했다면 최초 검사는 `1/3`, 2차 판정을 최종으로 인정하는 조건에서는 최종 `2/3`, 전체 시도는 `2/4`다. 목적에 맞는 하나를 선택하고 나머지와 구분한다.

재검사 여부를 식별하지 못하면 임의로 `drop_duplicates` 하지 않는다. 원본에서 정책을 적용한 분석 테이블을 별도로 만들고, 선택·제외한 시도 수와 정책을 기록한다. 공개 키트의 집계 도구는 이 업무 정책을 대신 결정하지 않는다.

## 조인: 늘어난 행은 늘어난 생산량이 아니다

결합 전 양쪽의 키 유일성과 원하는 관계를 확인한다. 예를 들어 wafer 검사 집계 1행에 결함 기록 3행을 붙이면 검사 수가 세 번 반복될 수 있다. 같은 키가 왼쪽 2행·오른쪽 3행이면 6행으로 불어나는 경우를 작은 예제로 확인한다.

결합 후 다음을 대조한다: 매칭·미매칭 키 수, 원본 고유 개체 수, 늘어난 행의 이유, 분자·분모 총계. 필요하면 결함을 원하는 단위로 먼저 집계한 뒤 결합한다. 누락 키끼리 매칭되지 않게 처리한다.

pandas가 이미 있다면 `merge(validate="many_to_one", indicator=True)` 같은 관계 검사와 매칭 표시를 사용할 수 있다. `many_to_many`는 유일성 검증을 하지 않으며, pandas는 양쪽의 null 키를 서로 매칭할 수 있어 일반 SQL과 다르다. 도구 사용 여부와 관계없이 같은 조건을 확인한다. [pandas.merge 공식 문서](https://pandas.pydata.org/docs/reference/api/pandas.merge.html)

## 실무자에게 확인할 질문

- 이번 결정은 어느 제품·공정·검사 단계·기간·모집단에 대한 것인가?
- 한 행은 제품, 검사 시도, 결함 사건 중 무엇이며 유일 키는 무엇인가?
- 분모에서 미검사·진행 중·중단·dummy/edge die를 어떻게 다루는가?
- 재검사·수리 후 통과를 인정하는가? 인정한다면 어떤 상태와 순서로 최종 판정을 고르는가?
- 결측 수량과 서로 다른 단위의 변환을 허용하는가? 제공된 기준표가 있는가?
- 집계 결과로 누가 무엇을 판단하며, 비교 기준과 제출 양식은 어디에 정의되어 있는가?
