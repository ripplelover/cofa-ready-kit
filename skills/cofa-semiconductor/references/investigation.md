# 결함 조사와 예측 검증

## 결함 Pareto를 만들 때

먼저 세는 것이 결함 사건인지, 불량 die인지, 실패한 테스트 항목인지 확인한다. 같은 die에 여러 label이 있을 때 사건 건수 합계와 불량 die 수는 달라진다. 카테고리 매핑·미분류·다중 label 정책을 기록한다.

가상 예: A 6건, B 3건, C 1건이면 사건 기준 누적 비중은 60%, 90%, 100%다. 이것이 전체 die의 60%가 A 때문에 불량이라는 뜻은 아니다. 범주를 건수 내림차순으로 정렬하고 동점 처리, 전체 사건 수, 제외·미분류 수를 표시한다. “80/20 법칙”을 데이터에서 확인하지 않고 사실처럼 붙이지 않는다.

장비 A의 결함이 더 많아도 생산량·검사량이 더 많을 수 있다. 같은 제품·기간·검사 방식에서 사건 건수와 노출량당 빈도를 나란히 본다. 조사 우선순위에 심각도나 손실 비용을 쓰려면 제공된 기준이 있어야 한다. 임의의 비용·가중치를 실제 업무 값처럼 만들지 않는다.

## 원인 후보를 다루는 방법

결과를 **관찰 → 가능한 설명 → 추가 확인**으로 분리한다. 예를 들어 “특정 챔버에서 이 기간의 실패 비율이 높다”는 관찰 뒤, 제품 구성·recipe 변경·검사 시점·센서 교정·소량 표본을 대안 설명으로 확인한다. 검사에서 발견한 시점과 결함이 만들어진 공정 시점도 다를 수 있다.

NIST는 산점도의 연관성이 인과관계를 입증하지 않는다고 설명한다. 따라서 상관계수·특성 중요도·Pareto 상위 항목만으로 근본 원인을 확정하지 않는다. [NIST Scatter Plot](https://itl.nist.gov/div898/handbook/eda/section3/eda33q.htm)

실무자가 확인할 다음 증거를 구체적으로 적는다: 같은 제품의 전후 기간, 같은 시간대 다른 챔버, 정비·recipe 변경 이력, 측정기 교정 여부. 이 키트는 실험이나 실제 장비 변경을 실행하지 않는다.

## 예측 과제일 때만 모델링

먼저 “어느 시점에 무엇을 예측하여 어떤 결정을 돕는가”를 정한다. 단순 집계나 보고서로 요구사항이 충족되면 예측 모델을 추가할 이유는 없다.

예측에 필요한 경우 다음 표를 작성한다.

| 항목 | 확인할 내용 |
| --- | --- |
| 대상·라벨 | die/wafer/lot 중 무엇이며 최초 실패·최종 실패 중 어느 결과인가 |
| 예측 시점 | 이 단계에서 실제로 사용할 수 있었던 파일·센서 구간은 어디까지인가 |
| 분할 목적 | 미래 생산분, 새로운 lot, 새로운 장비 중 어디에 일반화하려는가 |
| 평가 | 놓친 불량과 과도한 재검사 중 어느 비용을 줄이며 비교 기준은 무엇인가 |
| 단순 기준 | 기존 규칙·훈련 구간의 대표값 등 최소 기준보다 나아지는가 |

라벨 이후의 final bin, 재검사 결과, 미래 구간의 센서 통계는 예측 당시 정보가 아닐 수 있다. 각 특징의 값뿐 아니라 **사용 가능 시각**을 점검한다. 정규화·결측 대체·특징 선택도 학습 자료에서만 적합해야 한다. [scikit-learn Data Leakage](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)

같은 lot/wafer의 서로 관련된 행이 양쪽에 섞이면 새로운 그룹 성능을 과대평가할 수 있다. `GroupKFold`는 그룹 겹침을 막지만 시간순서를 보장하지 않는다. `TimeSeriesSplit`은 과거→미래 검증을 돕지만 lot 분리를 대신하지 않는다. 두 조건이 모두 필요하면 두 제약을 만족하는 분할을 별도로 검증한다. [scikit-learn Cross-validation](https://scikit-learn.org/stable/modules/cross_validation.html)

분할을 검사하는 최소 조건: 훈련·평가 개체 키 교집합, 목적상 분리할 그룹의 교집합, 훈련 정보 사용 시각과 평가 예측 시점의 순서, 라벨 확정 지연, 겹치는 센서 창. 날짜 경계를 걸치는 lot는 제외·한쪽 배정 등 선택을 기록한다. 시간 간격이 불규칙하면 같은 행 수가 같은 평가 기간을 뜻하지 않는다.

평가셋을 보면서 임계값·특징·모델을 반복 선택하면 최종 평가가 오염된다. 작은 검증 구간으로 선택하고 남겨둔 평가 구간으로 한 번 확인한다. 희소한 불량은 전체 정확도만 보고하지 말고 실제 TP/FP/FN/TN, 대상 수, 사용한 임계값과 선택 근거를 함께 남긴다. 수치가 높아도 인과관계나 실제 배포 효과를 증명하지 않는다.
