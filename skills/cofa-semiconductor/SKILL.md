# 반도체 데이터를 실행 가능한 분석으로 바꾸기

제출 확정 전용이다. 확정 후에는 질문 준비 대기 중에도 이 스킬과 AI 작업을 중단한다.

실제 README·데이터 사전·제공 파일에서 출발한다. 반도체 기업의 대회라는 이유로 수율 예측·HBM·대시보드가 과제라고 추정하지 않는다. 사용자가 요구한 결과와 남은 시간에 맞춰 최소 분석을 구현하고, 계산의 의미를 확인한다.

## 먼저 확정할 계약

현재 자료에서 **한 행의 의미, 식별 키, 검사 단계, 시간·단위, 분자·분모, 결측·재검사 정책**을 확인한다. 명시된 값과 가정을 나누고, 분석 결과를 바꾸는 미확정 조건만 실무자에게 물을 질문으로 정리한다. 답변을 기다리는 동안 원본 보존·스키마·키 중복 점검은 진행한다. 중요한 분모나 재검사 정책을 추측해 최종 수율을 확정하지 않는다.

## 필요한 참고만 읽기

| 현재 작업 | 읽을 자료 | 먼저 만들 결과 |
| --- | --- | --- |
| 수율·검사 집계, 파일 결합, 재검사 | [데이터 계약과 수율](references/data-contract.md) | 검사 모집단과 키가 명시된 집계 및 작은 손계산 대조 |
| 설비 연속값, 이상 신호, 공정능력 | [SPC 적용과 한계](references/spc.md) | 동일 조건 시계열과 고정 기준기간, 계산값·경보·한계 |
| 결함 Pareto, 원인 후보, 예측 모델 | [조사와 검증 설계](references/investigation.md) | 관찰·가설·추가 확인을 구분한 우선순위 또는 누수 없는 검증안 |

여러 CSV의 키 결합이 실제로 필요하면 [조인 사전 검사](references/data-contract.md#로컬-도구로-조인-전제-확인)로 관계와 예상 행 수를 확인하고, 실제 결합 후 분자·분모 보존은 별도로 검증한다.

## 구현에서 지킬 구분

- `defects`는 결함 **건수**일 수 있다. 불량 **개체 수**로 간주해 `1 - defects/tested`를 수율로 만들지 않는다.
- `sum(passed)/sum(tested)`는 같은 기준의 서로 겹치지 않는 검사 모집단일 때만 합친다. 행별 비율 평균과 구별한다. 분모가 0이거나 없으면 산출 불가로 표시한다.
- wafer·die·package, 최초 검사·최종 검사의 단위를 섞지 않는다. 재검사를 무조건 중복 삭제하거나 모두 더하지 않는다.
- 조인 전후 행 수·개체 수·분자·분모 보존을 확인한다. 다대다 결합으로 증가한 수량을 실제 생산량처럼 보고하지 않는다.
- 관리한계 이탈은 조사할 신호다. 규격 불합격·원인 확정·설비 정지 명령과 구분한다. 실제 규격·안정성·분포 조건 없이 Cpk나 임의 합격선을 만들지 않는다.
- 예측 과제는 예측 시점에 알 수 있었던 특징만 사용한다. 평가 목적에 맞춰 lot/wafer 그룹 또는 미래 기간을 분리하며, 전처리는 학습 부분에서만 적합한다.

## 마칠 때

확인된 요구사항 하나가 **입력 → 계산/구현 → 검증 → 해석**으로 이어지게 한다. 결과에 모집단·기간·단위·제외 수·검증 사례와 남은 한계를 붙인다. 코드 실행 성공과 통계적 가정 확인을 따로 보고한다. 과제가 요구하지 않으면 모델·웹앱·외부 도구를 추가하지 않는다.

이 스킬은 제공 데이터를 읽고 분석 산출물을 만드는 용도다. 실제 설비 제어, recipe 변경, MES 승인·lot 해제는 수행하지 않는다. 시험에서는 제공 Codex와 허용 모델을 사용하고 문제·데이터·결과물을 외부 서비스로 보내지 않는다. 공개 기술 검색에는 시험 내용을 싣지 않는다. 후속 서술형 단계에는 사용하지 않는다.
