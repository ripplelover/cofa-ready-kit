## 1. 키트 받기

**Cofa 안의 일반 터미널**, 실제 과제 폴더에서 아래 한 줄을 실행합니다. `Ask Codex` 입력칸에 넣는 셸 명령이 아닙니다.

```bash
git clone --depth 1 https://github.com/ripplelover/cofa-ready-kit.git .cofa-kit
```

왼쪽 파일 목록에서 **`.cofa-kit` → `README.md`**를 엽니다. 시험 중에는 외부 브라우저로 GitHub에 들어가지 않고 이 로컬 파일을 봅니다. 과제 폴더의 원래 `README.md`는 **문제**, `.cofa-kit/README.md`는 **이 사용법**입니다. 작업 위치는 실제 과제 폴더로 유지합니다.

파일을 못 찾으면 파일·에디터 영역을 선택한 뒤 **Ctrl+P**로 `.cofa-kit/README.md`를 검색합니다. 문서 링크가 클릭되지 않으면 왼쪽 파일 목록에서 링크에 적힌 경로를 엽니다.

이미 `.cofa-kit`이 있거나 다운로드가 실패하면 지우거나 반복 실행하지 말고 제공 Codex에 현재 상태와 원인을 확인해 달라고 요청합니다. 받지 못하더라도 실제 문제 자료로 작업을 진행할 수 있습니다.

## 2. 제공 Codex에 시작 요청 보내기

**OpenAI Codex / Ask Codex 입력칸**을 엽니다. 일반 터미널만 있으면 `codex`를 실행합니다. 실제 제공된 허용 모델을 사용하며 개인 로그인·API 키를 추가하지 않습니다.

아래 전체를 **제공 Codex 입력칸**에 복사합니다. 아직 과제를 제출 확정하기 전이어야 합니다.

```text
아직 과제 제출 확정 전이야.
.cofa-kit/prompts/SCENARIO.md를 읽고 실제 과제를 진행해 줘.
현재 위치와 실제 문제 README·제출 조건부터 확인해 줘.
키트의 README와 examples는 실제 시험 문제가 아니야.
각 단계에 맞는 스킬을 네가 골라 필요한 SKILL.md만 직접 읽고 적용해 줘.
SCENARIO의 선택 기준으로 연결된 허용 MCP 도구 중 필요한 것만 골라 써 줘.
cofa_local은 로컬 자료 검사에, 내가 연결한 공식 openai_docs는 시험 내용 없는 공개 기술 질의에만 써 줘.
필요 없는 도구는 호출하지 말고, 미연결·실패 시 CLI나 기존 도구로 진행해 줘.
기존 파일·작업 기록을 보존해 줘.
기능 작업이 끝날 때 실제 한 일과 근거를 기록하고, 제출 준비 때 작업 내역을 정리해 줘.
먼저 실제 요구사항·필수 제출물·내가 실무자에게 물어볼 질문을 짧게 정리해 줘.
설치나 MCP 연결에 막히면 가능한 기존 도구로 진행하고 미검증을 알려 줘.
화면 조작과 제출은 내가 직접 할게. 제출 확정 후에는 AI 작업을 중단해 줘.
```

첫 응답에서 **실제 문제 파일을 읽었는지, 필수 제출물이 무엇인지** 확인합니다. 업무 질문은 오른쪽 **실무자 에이전트에 본인이 보내고**, 받은 답을 Codex에 전달합니다. 사용법은 Cofa Helper, 반복 장애는 문제 신고로 문의합니다.

## 3. 진행하면서 필요한 말만 복사하기

**업무 답변을 전달한 뒤 구현할 때:**

```text
확인된 조건부터 구현하고 관련 검증까지 진행해 줘.
변경 파일·실제 실행 결과·남은 문제·내가 할 일만 짧게 알려 줘.
```

**수정이 끝나 검증할 때:**

```text
실제 요구사항과 대조해 정상·오류·경계 사례를 확인해 줘.
마지막 수정 이후의 검사 결과를 확인하고 실패·미검증·필수 누락을 구분해 줘.
```

**제출을 확정하기 전에:**

```text
실제 필수 문서를 구현·검증 기록에 맞춰 정리해 줘.
작업 내역을 구현 기능·AI 활용·내가 확인한 판단·검증 결과·남은 한계로 나열해 줘.
내가 설명해야 할 문제 정의·선택 이유·검증 근거·남은 한계를 짚어 줘.
필수 파일의 실제 경로와 내가 직접 확인할 항목을 알려 줘.
```

시간이 줄어들면 `화면의 남은 시간은 __분이야. 필수 오류와 제출 준비를 우선해 줘.`라고 실제 시간을 전달합니다. 작업 종료 **10분 전부터** 본인이 저장·필수 파일·제출 화면을 확인합니다.

**제출 확정 뒤에는 AI·Skill·MCP 사용을 중단합니다.** 키트는 Cofa의 제출 상태를 감지해 자동 차단하지 않으므로 본인이 사용을 멈춰야 합니다. 후속 서술형은 AI와 복사/붙여넣기 없이 직접 답합니다. 최종 업로드 후 완료 화면의 제출 ID·시각·파일 수·크기를 확인합니다. [화면별 상세 안내](docs/EXAM-PLAYBOOK.md)

### 작업이 끝나면 무엇을 했는지 보기

위 **시작 요청**을 보냈다면 Codex가 기능 작업마다 중요한 내역을 짧게 기록하고, 작업 완료·제출 준비 때 다음을 정리하도록 연결돼 있습니다. 스킬 이름을 다시 고르거나 MCP를 추가할 필요가 없습니다.

| 정리 항목 | 확인할 내용 |
| --- | --- |
| **구현한 기능** | 원래 기능과 이번 변경, 관련 파일, 구현·부분 구현·미구현 상태 |
| **AI가 한 일** | 실제 분석·코딩·오류 수정·검증·문서 작성에서 도움받은 부분 |
| **내가 판단·확인한 일** | 내가 전달한 조건·확인한 선택·직접 점검한 결과. 기록이 없으면 확인 필요로 표시 |
| **검증 결과** | 실제 실행한 검사·결과·근거, 마지막 수정 후 미검증인 부분 |
| **남은 한계** | 실패·미완료·임시 가정, 아직 실행하지 않은 개선 후보 |

이미 작업 중이거나 목록이 안 나오면 **제출 확정 전에 제공 Codex 입력칸**에 이것만 보냅니다.

```text
아직 제출 확정 전이야. .cofa-kit/skills/cofa-explain/SKILL.md를 읽고 작업 내역을 정리해 줘.
실제 파일·현재 대화·검증 기록으로 확인되는 기능과 AI 활용을 나열해 줘.
내가 판단하거나 확인했다는 근거가 없으면 추정하지 말고 확인 필요로 표시해 줘.
기존 작업 기록이 있으면 보존하며 갱신하고 경로를 알려 줘. 없으면 우선 여기 보여 줘.
```

목록을 읽으며 **정말 구현됐는지, 왜 그 선택을 했는지, 무엇을 확인하지 못했는지** 본인이 확인합니다. 이는 제출 전 작업 기록이며 실제 서술형 답안이 아닙니다. 확정 뒤에도 기록을 열람할 수 있다고 가정하지 말고, 후속 문항은 AI·복사/붙여넣기 없이 직접 답합니다.

## 4. 특정 스킬을 직접 쓰고 싶다면

**매번 스킬을 직접 고를 필요는 없습니다.** 위 시작 요청으로 Codex에 선택을 맡깁니다. 아래는 직접 지정하고 싶을 때만 쓰는 메뉴입니다. 반도체 분석에는 해당 스킬, 실제 예측 모델 과제에는 모델 평가 스킬을 골라 읽도록 진행 지침에 연결했습니다.

MCP도 **연결되어 실제 도구 목록에 보이는 것 중에서** Codex가 필요한 도구를 고릅니다. 로컬 검사에는 `cofa_local`의 6개 도구 중 필요한 것을, 공개 OpenAI 기술문서가 필요하면 선택해 연결한 `openai_docs`를 사용하도록 구성했습니다. **여러 개를 준비해 두되 매번 모두 호출하지 않습니다.** `git clone`만으로 스킬 목록 등록이나 MCP 연결까지 되는 것은 아닙니다. MCP가 없으면 CLI·기존 도구로 진행합니다.

| 지금 할 일 | 스킬 파일 |
| --- | --- |
| 문제·요구사항·업무 질문 정리 | [cofa-triage](skills/cofa-triage/SKILL.md) |
| 구현 또는 기존 코드 수정 | [cofa-build](skills/cofa-build/SKILL.md) |
| 실제 결과·오류·경계 검증 | [cofa-verify](skills/cofa-verify/SKILL.md) |
| 제출 확정 전, 작업·AI 활용 내역 정리와 본인 설명 연습 | [cofa-explain](skills/cofa-explain/SKILL.md) |
| 반도체 검사·수율·lot/wafer·계측 분석 | [cofa-semiconductor](skills/cofa-semiconductor/SKILL.md) |
| 실제 분류·회귀 예측 모델의 학습·평가 | [cofa-model-eval](skills/cofa-model-eval/SKILL.md) |

예를 들어 반도체 분석과 검증을 같이 시킬 때도 **설치 없이 파일 두 개를 읽게 하면 됩니다.**

```text
.cofa-kit/skills/cofa-semiconductor/SKILL.md와
.cofa-kit/skills/cofa-verify/SKILL.md를 읽고 적용해 줘.
먼저 단위·분모·재검사 기준을 확인하고, 분석 후 실제 결과를 검증해 줘.
미확인 업무 기준과 실행하지 못한 검사는 구분해서 알려 줘.
```

`$스킬이름`으로 호출하는 방법은 [선택형 설치·여러 스킬 사용법](docs/SKILLS-BEGINNER.md)에 있습니다. 기본 사용에는 설치가 필요 없습니다.

### MCP를 연결하고 싶다면

사전 체험에서 확인한 최상위 이름은 **`mcpServers`**입니다. 아래 명령은 **로컬 검사 + 공식 문서, 두 서버의 설정 후보**를 만듭니다. 화면의 로컬 `command`·`args`와 원격 HTTP `url` 지원을 확인한 뒤 직접 저장합니다. 초기 Codex CLI에서도 스킬은 그대로 읽어 사용할 수 있습니다.

1. **일반 터미널**의 실제 과제 폴더에서 다음을 실행합니다.

```bash
python3 .cofa-kit/scripts/install.py --workspace . --mcp-json --with-openai-docs
```

2. **Cofa MCP 탭**의 `mcpServers` 안에 출력된 `cofa_local`·`openai_docs`를 추가하고 저장합니다. 기존 서버는 보존합니다. 원격 `url` 지원이 확인되지 않으면 명령 끝의 `--with-openai-docs`를 빼서 **로컬 서버만** 생성·연결합니다. 생성기는 설정 출력만 하며 네트워크 연결·설정 저장·스킬 설치를 하지 않습니다.
3. **제공 Codex**에 `cofa_local의 profile_csv를 실제 호출해 .cofa-kit/examples/defects.csv를 요약해 줘. 도구가 없거나 실패하면 그대로 알려 줘.`라고 요청해 연결을 확인합니다. `openai_docs`도 추가했다면 시험 자료를 포함하지 않은 `Codex MCP 연결 상태 확인 방법` 같은 일반 기술 질의로 별도 확인합니다.

연결 후에는 **2번의 시작 요청만** 보내면 됩니다. 이미 작업 중이면 `아직 제출 확정 전이야. .cofa-kit/prompts/SCENARIO.md를 다시 읽고 현재 연결된 허용 MCP와 스킬 중 필요한 것만 골라 기존 작업을 이어가 줘.`라고 보냅니다. 새 기능을 위해 매번 스킬·도구 이름을 지정할 필요가 없습니다.

| 추가 후보 | 사용할 때 |
| --- | --- |
| **cofa_local** | 로컬 CSV·반도체·검증 기록 검사. 6개 도구 중 과제에 맞는 것만 선택 |
| **OpenAI Docs MCP** | 선택해 연결한 경우 공개 OpenAI/Codex 문서가 필요할 때 사용. 시험 자료 없이 일반 기술 질의만 전송 |
| **CLI 플러그인** | `codex plugin --help`로 실제 지원을 확인한 뒤 필요한 공개 지침·도구만 검토 |

서버별 JSON 예제, 플러그인 확인 순서, Context7 등 기본 구성에서 제외한 후보의 이유는 **[MCP·플러그인 상세 안내](docs/MCP-PLUGINS.md)**에 모았습니다. 자동 선택은 Codex가 이 지침을 적용하는 흐름이며 별도 실행 서비스나 규칙 차단 장치가 아닙니다. 원격 서버 자동 연결이나 새 플러그인 자동 설치는 하지 않으며 실제 Cofa의 HTTP 지원을 확인해야 합니다. CLI 교체나 개인 인증·권한 변경도 필요하지 않습니다.
