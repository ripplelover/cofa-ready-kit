# Cofa Ready Kit

**180분 안에 문제를 이해하고, 작동하는 결과를 만들고, 검증 근거와 본인의 설명을 남기기 위한 준비 도구.**

SK하이닉스 AI 해커톤 2026 2차 예선을 앞두고 만든 비공식 범용 키트입니다. 실제 문제·정답·채점표를 포함하지 않습니다. 본선 진출이나 순위를 보장하지 않습니다. 2026-10-30에 제공된 안내문을 기준으로 준비했으며 당일 공지와 과제 README가 우선합니다.

**처음 쓰면 [단계별 사용 매뉴얼](docs/MANUAL.md)부터 읽으세요.** 명령을 입력할 위치, 정상 출력, 오류 복구, Codex에 맡길 요청을 순서대로 설명합니다. 반도체 문제가 주어졌다면 [반도체 실행 실습](docs/SEMICONDUCTOR-WALKTHROUGH.md)과 [반도체 과제 안내](docs/SEMICONDUCTOR.md)를 필요한 부분만 읽으세요. 반도체 출제가 확정됐다는 뜻은 아닙니다.

**[10월 30일 실제 리허설 결과](docs/REHEARSAL-2026-10-30.md)**도 추가했습니다. 새 공개 복제본에서 합성 반도체 과제를 구현하고 자체 10개·독립 18개 테스트, 로컬 스킬 탐색, MCP 직접 호출을 확인했습니다. Cofa에서 아직 확인할 부분과 발견한 실행 환경 차이도 기록했습니다.

**[초보자용 여러 스킬 사용법](docs/SKILLS-BEGINNER.md)**: 어디에 입력하는지부터 한 단계씩 따라가고, `triage + semiconductor`, `build + verify` 조합을 그대로 요청할 수 있습니다.

**[문제를 받은 뒤의 당일 실행 안내](docs/EXAM-PLAYBOOK.md)**: 첫 15분, 실무자 질문, 과제 유형별 선택, 180분 운영과 최종 완료까지 설명합니다. **v1.2.0**에는 두 CSV의 중복 키·미매칭·예상 결합 행 수를 검사하는 [조인 도구](docs/DATA-JOIN.md)를 추가했습니다. 스킬은 5개를 유지하고 로컬 MCP 도구는 5개가 됐습니다.

## 먼저 알아야 할 시험 구조

| 단계 | 해야 할 일 |
|---|---|
| 과제 최대 180분 | 제공된 Codex로 문제 정의, 구현, 검증, 필요한 제출 문서 작성 |
| 질문 준비 대기 | 제출물이 고정되며 후속 문항이 준비됨 |
| 서술형 6문항 × 5분 | **AI·복사/붙여넣기 없이 본인이 직접 답변** |
| 최종 완료 | 완료 화면의 제출 ID·시각·파일 수·크기 확인 |

응시는 **2026-10-31 10:00–14:00 KST**, 접속 준비는 09:40까지입니다. 공개 도구를 가져올 수 있지만 시험 문제·파일·결과물의 외부 전송과 Git Push는 금지됩니다. Astra, 외부 AI·개인 API 키, Computer Use도 사용할 수 없습니다. 자세한 구분은 [규칙 요약](docs/RULES.md)을 읽으세요.

## 들어 있는 것

| 구성 | 쓰는 순간 | 얻는 것 |
|---|---|---|
| `cofa-triage` | 처음 문제를 읽을 때 | 요구사항, 중요한 질문, 완료 기준 |
| `cofa-build` | 구현할 때 | 기존 구조를 활용하는 작은 완성 경로 |
| `cofa-verify` | 기능 검증·제출 점검 | 정상·예외 검증, 미완료 항목 확인 |
| `cofa-explain` | **서술형 시작 전** 이해도 연습 | 자신의 선택·근거를 말로 설명하는 훈련 |
| `cofa-semiconductor` | 반도체 데이터·분석 과제일 때 | 검사 단위·분모·재검·공정 조건 확인, 목적에 맞는 계산·검증 |
| `cofa_kit` CLI | 데이터 확인·기록·검증 | CSV/JSON 요약, 실행 증거, 요구사항 검사 |
| `semi yield` / `semi spc` | 집계 검사 데이터 / 연속 계측 데이터 | 가중 통과율, 고정된 과거 기준의 I-MR 신호 검사 |
| `data join-check` | 두 CSV를 키로 결합하기 전 | 키 유일성·미매칭·예상 결합 행 수. 실제 수량 보존은 별도 검증 |
| 로컬 MCP, 선택 | 도구 호출로 검사하고 싶을 때 | 파일 검사·CSV 요약·가중 통과율·I-MR·CSV 키 관계 검사 |

Python 3.10 이상이면 핵심 도구가 동작합니다. `pip install`, API 키, 원격 MCP, 추가 AI 구독이 필요하지 않습니다. MCP 연결에 문제가 있어도 동일 기능을 CLI로 쓸 수 있습니다.

## 내일 가져오는 명령

**Cofa가 제공한 작업 공간의 터미널**에서 공개본을 가져옵니다. 오늘 개인 PC에서 준비하는 것과 내일 시험 환경을 혼동하지 마세요. 개인 PC 파일을 시험장에 업로드하는 방식은 지원되지 않습니다.

```bash
git clone --depth 1 https://github.com/ripplelover/cofa-ready-kit.git .cofa-kit
python3 .cofa-kit/scripts/install.py --workspace .
python3 .cofa-kit/scripts/cofa.py doctor
```

이미 `.cofa-kit` 폴더가 있으면 덮어쓰지 말고 기존 복사본을 확인하세요. Python 명령이 `python`으로 제공되면 `python3` 대신 사용합니다. 설치는 작업 폴더의 `.agents/skills/`에 스킬만 복사합니다. 기존 `AGENTS.md`, Codex 인증, 감독 설정을 수정하지 않습니다.

그다음 제공된 `codex`를 실행하고 `/status`, `/model`에서 안내된 허용 모델을 확인하세요. 스킬이 발견되면 아래 첫 요청을 사용합니다.

```text
$cofa-triage
현재 과제 README와 제공 파일을 읽고 필수 제출물, 사용자 문제, 완료 기준을 정리해 줘.
사실과 가정을 구분하고, 구현을 바꿀 중요한 질문만 뽑아 줘.
남은 시간은 [실제 시간]분이다. 아직 실제 문제를 확인하지 않은 내용은 추측하지 마.
```

스킬이 안 보이면 자동 탐색에 시간을 쓰지 말고 다음처럼 요청하세요.

```text
.cofa-kit/skills/cofa-triage/SKILL.md를 읽고 현재 과제에 적용해 줘.
```

이 명령과 스킬은 사전 체험에서 확인할 대상입니다. **Cofa 실제 환경에서 연결이 검증됐다고 주장하지 않습니다.** 자세한 설치·복구·MCP 방법은 [설치 설명서](docs/SETUP.md)에 있습니다.

## 가장 효과적으로 쓰는 순서

0. [단계별 사용 매뉴얼](docs/MANUAL.md): 설치부터 결과 확인·제출 전 점검까지 한 번 따라갑니다.
1. [오늘과 내일 운영표](docs/DAY-PLAN.md): 사전 체험 15분을 쓰기 전에 읽습니다.
2. [도구 사용 예제](docs/TOOLS.md): `init → log/run → check → report`를 합성 데이터로 한 번 해봅니다.
3. [연습 과제](docs/PRACTICE.md): 실제 시험과 무관한 작은 문제로 구현·검증·자기 설명을 연습합니다.
4. [프롬프트 모음](prompts/README.md): 시작, 맥락 복원, 오류 복구, 최종 검증 요청을 골라 씁니다.
5. [공개 자료 조사](docs/RESEARCH.md): 참고한 저장소와 공식 자료, 확인 범위를 봅니다.

반도체 데이터가 주어지면 [전용 실습](docs/SEMICONDUCTOR-WALKTHROUGH.md)에서 **99/100과 1/2의 전체 통과율은 100/102 ≈ 98.0392%**임을 직접 확인해 보세요. 로트별 퍼센트의 단순 평균인 74.5%와 다릅니다. I-MR 예제는 과거 기준과 이후 관측을 분리하며, 이상 신호를 원인 확정이나 제품 불합격 판정으로 해석하지 않습니다.

필수 파일명은 과제 안내를 따릅니다. 이 키트의 `requirements.json`, `decision-log.jsonl`은 개인 작업 보조 형식이며 공식 제출 양식이 아닙니다.

## 검증 범위

`doctor` 성공은 실행 환경을 찾았다는 뜻입니다. `check` 성공은 선언한 상태와 필수 파일·근거 파일의 구조가 맞는다는 뜻입니다. 어느 것도 과제 기능이 정확하다는 보장은 아닙니다. 실제 기능 테스트와 본인의 Browser 수동 확인을 함께 수행해야 합니다.

```bash
python -m unittest discover -s tests -v
```

이 명령은 **키트 자체를 검증**합니다. 시험 과제 테스트로 보고하지 마세요. 로컬 검증 결과와 남은 제약은 [검증 기록](docs/VALIDATION.md)에 적습니다.
