# 당일 시나리오를 따라가는 시작·재개 요청

아래는 **제공된 Codex의 대화 입력란**에 넣는 일반 요청문이다. 터미널 명령이나 새 스킬이 아니다. 과제 제출물 확정 전에만 사용한다. 설치와 단계별 진행은 [당일 실행 안내](../docs/EXAM-PLAYBOOK.md)를 따른다.

## 처음 시작할 때

공개 키트를 과제 폴더의 `.cofa-kit`으로 받은 뒤 아래를 입력한다. 다른 이름으로 받았다면 경로만 실제 이름으로 바꾼다.

```text
.cofa-kit/docs/EXAM-PLAYBOOK.md를 읽고 현재 과제를 단계별로 진행해 줘.
먼저 현재 작업 위치와 실제 과제 안내 파일의 경로를 확인해 줘.
.cofa-kit 안의 README, examples, 문서는 준비자료이며 실제 시험 문제가 아니야.
실제 과제 안내와 당일 운영 안내를 기준으로 요구사항과 제출물을 확인해 줘.
키트 파일을 읽을 수 없으면 그 사실을 밝히고 실제 과제 자료로 가능한 작업을 진행해 줘.

실제 파일과 실행 증거로 현재 단계를 찾고 다음에 필요한 작업을 시작해 줘.
과제 안내와 원본 입력 데이터는 보존하고, 필요한 과제 코드 수정과 산출물 작성은 진행해 줘.
이미 있는 작업 기록을 활용하고 새 추적 파일이나 고정 제출 파일명을 강제하지 마.
반도체 분석이나 CSV 조인 도구는 실제 요구에 맞을 때만 사용해 줘.
내가 알려 준 화면의 남은 시간이 있으면 계획에 반영하고, 모르면 시간을 추정하지 마.

명확한 범위의 조사·구현·검증은 매번 확인을 기다리지 말고 진행해 줘.
업무 기준이 불명확해 결과가 달라질 때만 내가 실무자에게 전달할 질문을 정리해 줘.
화면 조작·감독 연결·제출은 내가 직접 할게. 자동으로 조작하지 마.
제출 확정 뒤에는 AI 작업과 설명 연습을 중단해 줘.

각 구간이 끝나면 현재 단계 / 실제 확인한 결과 / 다음 작업 / 내가 직접 할 일을 짧게 알려 줘.
읽지 못한 파일이나 실행하지 않은 검사를 완료로 처리하지 마.
```

## 같은 대화에서 이어갈 때

다음 문장들은 **Codex에 보내는 대화 요청**이다. 실제 결과를 확인한 뒤 필요한 것을 골라 입력한다.

- “현재 결과를 기준으로 다음 단계 진행해 줘.”
- “실무자가 실제로 답한 기준은 다음과 같아. 이 기준을 반영해 진행해 줘.” 뒤에 받은 답을 적는다.
- “검증이 실패했어. 실제 오류와 재현 입력부터 확인하고 최소 수정한 뒤 관련 검사를 다시 실행해 줘.”
- “화면에서 확인한 남은 시간은 40분이야. 필수 누락과 제출 준비를 우선해 줘.”에서 숫자를 실제 값으로 바꾼다.

중요한 업무 기준의 답이 없으면 확정된 사실처럼 처리하지 않는다. 직접 수행한 Browser 확인 결과는 관찰한 내용만 전달한다.

## 대화가 길어졌거나 재접속했을 때

아직 제출 확정 전인 경우에만 아래를 사용한다. 현재 파일·기록을 확인하고 이어가며 이전 작업의 성공을 추정하지 않는다.

```text
아직 과제 제출물 확정 전이야. 새로 시작하지 말고 현재 작업을 이어가 줘.
.cofa-kit/docs/EXAM-PLAYBOOK.md와 실제 과제 안내, 현재 파일, 검증 기록을 확인해 줘.
키트 README와 합성 예제를 실제 과제로 취급하지 마.
완료되고 검증된 것 / 구현됐지만 미검증인 것 / 실패·누락 / 다음 행동을 짧게 정리해 줘.
기록과 코드가 다르면 차이를 밝히고, 이전 대화에서 성공했을 것이라고 추정하지 마.
기존 기록 형식을 유지하고 새 추적 파일을 불필요하게 만들지 마.
내가 알려 준 실제 남은 시간을 반영해 필요한 작업부터 계속해 줘.
사람이 해야 할 화면·업무 확인만 알려 주고 가능한 구현과 검증은 진행해 줘.
제출 확정 뒤에는 AI 작업을 중단해 줘.
```

**제출 확정 후에는 위 요청을 보내지 않는다.** [당일 실행 안내](../docs/EXAM-PLAYBOOK.md)의 사람만 수행하는 제출·후속 서술형·최종 완료 절차를 따른다. 실제 문제·파일·결과를 이 준비용 채팅이나 외부 AI에 보내거나 개인 PC 파일로 업로드하지 않는다.
